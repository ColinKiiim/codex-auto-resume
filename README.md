**Codex 频繁提示 at capacity，任务停下来后总要手动点继续？** CodexAutoResume 是一个 Windows 桌面小工具：识别并点击暂停三角形，通过白色方块确认恢复；底部还能查看当前登录账号的剩余额度与重置时间。单个 EXE，无需 API Key。

> 1.1.22 紧急移除暂停恢复路径的草稿检测，输入区内容不再阻止恢复；保留此前更新交接与遮挡/最小化修复，其他 TODO 未改动。见 [版本说明](docs/releases/v1.1.22.md)。

## 额度不足时暂停，恢复后继续

首页保留底部紧凑额度条，正常约每 10 秒读取本机当前登录账号，悬浮显示 5h / 周额度的准确本地重置时间。无需导入账号或管理令牌。额度控制位于设置中，默认关闭，还需要主界面的“自动恢复”开关。

选择 5h、周或两者，并分别设置各自的剩余阈值（均默认 10%）：任一所选额度小于等于阈值时，尝试核实原对话并点击运行方块暂停；等待时屏幕每分钟采样，额度仍独立查询。全部所选额度高于各自阈值后，优先重新确认并点击原对话的暂停三角形。三角形消失时，只向核实过的原对话空白输入框补发可自定义指令，默认“刚刚我中断了你的对话，请从上次中断处继续工作”。

输入优先使用目标已经开放且可核验的本机调试接口，适配多 app 页面和当前侧栏结构；不可用时尝试 Windows UI Automation，必要的焦点后备仅在未最小化时使用。不会为此自动开启调试、重启或还原 Codex。无法核实对话、接口不支持、已有草稿/附件/问答/语音状态或输入结果不明时，保留内容并等待人工处理，不重复发送。自有最小化窗口流程已验证，真实后台发送继续待验收，见 [本版实现记录](docs/history/2026-10-29-v1.1.19-background-controls.md)。

**官方提前统一重置额度也是目标场景。** 若全体用户额度早于原倒计时恢复，CAR 按最新实际额度判断，不等旧重置时间结束；这覆盖用户提出的 Tibo 全体重置情景。正常查询间隔约 10 秒，网络、失败退避、输入让行和界面可用性都会影响恢复速度。尽早继续请求可以减少闲置，但周窗口何时开始由服务端决定，CAR 不控制服务端计时，也不承诺重置瞬间恢复。

改变额度设置或继续文案会取消旧事务；若已由 CAR 暂停，设置变更会同时关闭自动恢复，避免意外继续。检测到用户手动继续时，本次暂停链路取消，直到额度恢复后再重新布防。关闭监测、切换目标或重启不会重放旧的补发指令。未完成的真实应用适配与实机验收保留在 [TODO](TODO.md)。

## 指定时间后恢复

在“设置 → 常规 → 定时恢复”选择完整日期和时间，点击“设置一次性恢复时间”，并开启主界面“自动恢复”。CAR 在指定时间前等待，到点后仍需满足已启用的各周期额度阈值、目标核验和连续 1.5 秒输入空闲；未知额度不会授权恢复。未开启额度控制时，也可只使用时间限制。

计划只限制恢复，不主动暂停正在运行的任务。恢复成功后计划结束；停止监测、关闭自动恢复、切换目标或退出取消计划。修改/取消已生效计划会关闭自动恢复，重新开启后才允许动作。计划不跨重启保存；有计划时更新重启也回到仅观察。电脑睡眠期间不执行或唤醒，唤醒后重新核对条件。时间或时区变化会取消计划并要求重新设置；不会到点新建对话或发送无关消息。

设置及辅助窗口在所属窗口附近居中，靠近屏幕边缘时限制在可用工作区；常规页可滚动至最后一项。

## 指定范围、一次性指令与历史

在设置中读取项目和聊天，选择后应用范围，再开启自动恢复。项目范围会在项目内轮询；切换前后核对当前项、工具栏和文档，需要时先激活 Codex 再投递一次原生切换，不移动鼠标、不重复导航。范围仅绑定当前 Codex 进程，重启、身份变化或切换结果不明后需要重新确认。

“一次性任务指令”与上方“定时恢复”分开：前者到点发送该任务保存的文案，后者只给现有恢复放行。先打开要绑定的聊天，填写时间和指令，新增任务。多个任务可同时保存、分别编辑或取消；到点可切回绑定聊天，同一聊天按到期顺序等待执行。已有草稿、运行中、账号不明、已启用额度不足或用户操作时等待。重启后重新绑定；结果不明不重试，并暂停该目标的后续任务，需人工核对或取消。

默认继续文案只服务普通额度恢复，不会动态覆盖已保存任务。任务时间、目标标题与文案只保存在本机 `timed-instructions.json`；账号绑定只保存摘要，不写入账号标识正文。

左下角“本轮已恢复”悬浮显示最近 24 小时最多四条已确认恢复，点击进入全部恢复历史；“完整记录”进入同一页面的全部活动。设置与记录均在主窗口内打开，监测继续运行，并保留暂停入口。

## Codex at capacity 频繁出现，应该怎么处理？

先看当前界面是否有可恢复的任务：

| 当前情况 | 如何处理 |
|---|---|
| 任务暂停，右下角出现向右三角形 | 本工具可以持续监测，在按钮稳定可识别时自动恢复 |
| 显示账号用量或重置时间 | 查看底部剩余额度和准确重置时间；可按需启用额度控制，点击不会增加额度 |
| 服务持续不可用，或没有恢复按钮 | 查看服务状态和客户端提示；本工具继续观察，不能替服务恢复容量 |
| 正在等待回答、确认权限或选择方案 | 由用户处理；本工具识别问答面板后等待 |
| 已变成白色方块、发送箭头或声波图标 | 普通恢复只观察；额度控制仅在核实本轮原对话后才可能暂停或补发 |

程序根据**窗口中的按钮图形**判断状态，不读取 `at capacity` 报错来诊断原因，也不修改 Codex、模型或账号设置。详细说明见 [Codex at capacity / atcapacity 常见问题](docs/troubleshooting.md)。

## 下载与开始使用

1. 打开本仓库的 **Releases**，下载最新版本附件 `CodexAutoResume-v版本-windows-x64.exe`。源码 ZIP 面向开发者。
2. 双击 EXE，并打开 Codex 桌面窗口。工具自动寻找目标，启动时只观察。
3. 核对识别结果，打开 **“自动恢复”**，无需快捷键或手动标定。
4. 新用户默认开启 **“后台监测”**，Codex 可以被其他窗口完全遮挡；已有接口可独立核验时也可保持最小化，接口不可用则等待。在设置中可切换监测方式和中英文界面。
5. 点击 **“暂停”** 停止监测，或关闭工具退出。

需要 Windows 10 1903+ / Windows 11 **x64** 和系统 .NET Framework。复制一个 EXE 即可迁移，图片、图标和许可证已内嵌，无需 Python、Node.js 或额外模型下载。问答面板识别使用 Windows 本机 OCR 语言。

本地构建后，程序也位于 `release/CodexAutoResume.exe`。[使用指南](docs/user-guide.md) 包含窗口选择、备用标定、快捷键和自测方法。

## 四种按钮，分别处理

| 图标 | 状态 | 工具行为 |
|---|---|---|
| ![右三角形恢复按钮](docs/images/resume.svg) | 暂停，可恢复 | 连续稳定识别后点击；点击前再次核对 |
| ![白色方块运行按钮](docs/images/running.svg) | 正在运行 | 确认恢复；额度控制在低额度及原对话可核实时可暂停 |
| ![向上箭头发送按钮](docs/images/send.svg) | 发送 | 普通恢复只观察；仅本轮额度恢复链路可在空框补发后发送 |
| ![声波语音按钮](docs/images/voice.svg) | 语音 | 只观察 |

蓝色引用编号和其他未知图形不列为自动按钮候选。多个真实按钮出现时持续扫描，恢复单候选后自动继续；也可从状态旁或高级设置中选择按钮区域。多个目标窗口需要用户选择。

## 适合长期工作的监测方式

- **窗口位置可变**：自动重新定位，手动标定保留作为备用。
- **遮挡后台模式**：通过窗口捕获和后台消息尝试恢复，不移动系统鼠标、不抢前台焦点。实际支持情况可用“后台自测”检查。
- **输入让行**：发现暂停三角形后等待连续 1.5 秒无鼠标/键盘输入；有输入重新计时，前后台一致，恢复不移动真实鼠标。
- **持续监测**：拖动窗口、暂时无法识别、捕获失败或未确认方块时继续观察，恢复点击至少间隔 5 秒。
- **安静监测**：固定状态行、小幅真实预览和可滚动的本轮时间戳进度展示工作状态，每 10 秒补一条短进度；完整活动记录仅保留有意义的变化；本机诊断日志每 10 秒记录一次。
- **自动更新**：启动及每 6 小时后台检查正式版，发现更新弹窗提示；确认后自动下载、校验、替换和重启，失败时保留或恢复旧版。
- **独立窗口**：自己的任务栏图标，方便切回查看。
- **当前账号额度**：底部细条正常约每 10 秒刷新，悬浮显示准确重置时间，点击查看账号来源与详情。复用已安装组件，无需另建账号系统；未开启额度控制时，额度不可用不影响普通恢复。

后台优先核验原窗口、聊天、页面与唯一输入区，直接读取动作状态并确认结果。首页“后台控件状态”是状态示意，实际图像仍标注“采样图”。接口不可用时保留图像后备；最小化时不使用缓存的 UIA 状态或图像点击，等待可核验接口。图像后备仍需目标提供新画面；正常静止不按时长报警，操作前独立取证、操作后新方块确认。Windows 的捕获边框取决于系统权限和其他捕获会话。详见 [后台模式](docs/background-mode.md) 与 [日志说明](docs/monitoring-logs.md)。

## 常见问题

**能彻底解决 Codex “Selected model is at capacity” 吗？**

它负责在恢复按钮出现时自动操作。服务是否接受下一次请求，仍由 Codex 和服务端决定。遇到持续报错，先核对服务状态、用量和客户端提示，见 [排查指南](docs/troubleshooting.md)。

**会自动发送输入框内容、回答问题或点停止吗？**

普通自动恢复只点击严格识别的右三角形。默认关闭的额度控制，开启后可在核实原对话的本轮流程中点击运行方块暂停，或补发自定义继续指令；已有草稿、无法核实或结果不明时等待人工处理。一次性任务仅发送用户保存的任务指令；不会回答问题或批准权限请求，普通启动仍只观察。

**能用于 Codex CLI、浏览器版、macOS 或 Linux 吗？**

当前实现面向 Windows x64 上的 Codex 桌面窗口。CLI 和浏览器的重试逻辑需要对应的实现。

**软件好像一直没动，怎么看是否还在工作？**

查看主窗口的监测状态；详细数据位于“设置 → 诊断工具”，其中“打开日志”可查看 `%LOCALAPPDATA%\CodexAutoResume\logs`。图标没有变化时不会每轮刷屏。

## 隐私与反馈

图像识别和 OCR 在本机完成。程序无需账号密码或 API Key，不自动上传画面，也不把问答文字、聊天标题或完整截图写入日志。诊断工具中的“保存按钮图”由用户主动触发，仅保存按钮区域。

反馈问题时，请在本仓库 **Issues** 提供工具版本、Codex 版本、Windows 版本、显示缩放、前台/后台模式和相关状态记录。涉及图标误识别时，可附不含对话内容的局部截图。[贡献指南](CONTRIBUTING.md) 说明了复现和验证方法。
