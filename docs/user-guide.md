# CodexAutoResume 使用指南

[首页](../README.md) · [常见问题](troubleshooting.md) · [English overview](../README.en.md)

## 安装与首次启动

从本仓库 Releases 下载 `CodexAutoResume-v版本-windows-x64.exe`，双击即可。使用 Windows 10 1903+ / Windows 11 x64 和系统 .NET Framework；程序的图片、图标与许可证均已内嵌。问答识别使用已安装的 Windows OCR 语言。

打开 Codex，等待工具识别窗口和右下角按钮。启动默认仅观察；核对目标后打开“自动恢复”开始。只有一个合适窗口时自动连接，多个目标窗口需选择。新用户默认后台监测；已有设置保留原选择。设置中支持简体中文 / English 即时切换。语言、前后台方式、手动区域大小和更新选项会保存在当前用户目录。普通启动仍只观察；更新重启可在核实原目标进程和窗口身份后恢复更新前状态，无法核实时退回仅观察。

## 前台与后台模式

前台模式要求 Codex 位于前台，按钮可见。1.1.11 起前后台都使用窗口消息，不移动真实鼠标；识别到暂停三角形后，连续 1.5 秒无鼠标/键盘输入才允许恢复，期间有输入重新计时，按键或鼠标按钮按住时不点击。工具不记忆“主动停止”意图：你手动停止后，若三角形仍在且连续空闲 1.5 秒，仍会自动继续。在“设置 → 常规”启用“后台监测”后，可以切到其他应用并把 Codex 完全盖住，保持 Codex 未最小化、未隐藏。后台通过窗口消息操作，不移动系统鼠标或激活目标。两个程序使用相同普通用户权限。

后台模式需要目标持续提供更新画面并接受消息。可以先用“后台自测”检查本机路径，再核对实际 Codex 暂停场景。最小化后等待还原。黄色边框是 Windows 的捕获指示，详见 [后台模式](background-mode.md)。

## 窗口移动与多个候选

自动定位跟随窗口移动。手动选择目标位于“设置 → 常规 → 高级定位 → 选择窗口”；首页只显示当前目标。状态旁或“设置 → 常规”的“选择按钮区域”可主动选择区域。

多个按钮候选出现时，只暂停点击，继续扫描。恢复单候选后自动继续原工作模式。取消区域选择也继续扫描。已经人工确认的区域按原位置跟踪；原区域消失或窗口布局变化时，可重新选择。蓝色数字引用等未知图形不进入自动候选。

## 定时恢复与设置窗口

“设置 → 常规 → 定时恢复”提供一次性的完整日期/时间选择，按当前本地时区解释。选择未来时间并点击“设置一次性恢复时间”，再开启“自动恢复”。到点只解除时间等待：启用额度控制时，全部所选周期仍须高于各自阈值；额度未知、草稿/问答、错误目标及用户输入保护仍生效。默认关闭，不会主动暂停任务或定时发送新消息。

首次确认恢复运行后计划结束。停止监测、关闭自动恢复、切换目标、关闭程序会取消计划；修改/取消已生效计划会关闭自动恢复，需重新开启。计划不跨进程保存；有计划时更新重启退回仅观察。电脑睡眠不唤醒，唤醒后取新证据；时钟或时区变化导致计划失效时需重新设置。普通自动恢复的 1.5 秒空闲规则不变。

设置、额度详情、活动记录、预览与更新窗口关联其所属窗口，打开时居中并限制在可用工作区，允许拖动且不全局置顶。常规/帮助页使用独立滚动区域，缩小窗口后也能查看末尾说明。

## 当前账号额度

1.1.14 起额度正常约每 10 秒查询，精确重置悬浮与点击动画同步提供。额度控制默认关闭，真实 Codex 接入与原遮挡专项验收限制见 [版本说明](releases/v1.1.15.md)。

首页底部恢复次数右侧显示简短周期、剩余额度细条和百分比。鼠标悬浮可直接查看各周期的准确重置日期与时间（本地时间，精确到秒）；缺失时间显示未知，旧数据会注明。点击摘要以短暂动画反馈，查看当前读取账号、登录来源、重置时间、最近成功读取时间及手动刷新；鼠标点击后不残留边框，键盘导航保留焦点提示。

正常额度查询约每 10 秒启动一次，前一次未结束时不会并发发起；失败按 2、4、8、15 分钟退避，成功后恢复正常间隔。未开启额度控制时，查询异常不影响原图像恢复；开启后需要有效额度才允许自动点击。

在“设置 → 常规”可开启“额度自动暂停与恢复”，默认关闭，需同时打开主界面“自动恢复”。选择 5h / 周或两者，分别设置各自阈值（0–99%，均默认 10%）；旧配置的共同阈值会迁移到两项，任一所选额度 ≤ 阈值则尝试核实对话并点击运行方块；全部所选周期 > 各自阈值才恢复。额度缺失、超过 30 秒未成功更新或查询失败不能授权恢复。等待期间只每分钟读取画面，独立额度轮询仍可提前发现官方统一重置，不受旧倒计时限制。

恢复时优先点击新画面中的暂停三角形；没有三角形时，仅向已核实的原对话空白输入框补发设置中的继续文案。后台 CDP 输入优先，仅发现并使用目标已开放且归属核实的本机接口；不自动开启调试或重启。后台写入未发生且明确不可用时可改用 UIA 焦点输入，Windows 可能拒绝激活；无法核实、已有草稿/附件/问题/语音或结果不明时需手动处理，不重复补发。这是随 1.1.14 提供的路径，尚未完成当前真实 Codex 的全链路验收，可能保持等待；先前实际范围见 [第二阶段记录](history/2026-10-26-stage-two.md)。

修改额度选项或文案取消旧事务；已由 CAR 暂停时，选项变更还会关闭自动恢复，文案编辑也会关闭自动恢复。检测到等待期间用户手动继续时取消本次额度暂停，并在额度恢复后才重新布防。停止监测、切换目标、重启不重放旧继续指令。未完成的真实应用适配/验收继续保留在 TODO，按用户明确指令随本版发布并披露限制。

CAR 隐藏调用当前目标安装目录内的 Codex App Server，复用本机登录，不提供账号导入、切换或登录页，不自行读取或保存令牌。普通安装的 `bin/codex.exe` 和商店安装的 `app/resources/codex.exe` 由目标程序路径定位，无需另装 Node/Python 或提供 API Key；如果该安装缺少支持的本机组件，则显示额度不可用。

查询使用当前 Windows 用户的 `CODEX_HOME`（未设置时为用户主目录下 `.codex`），并核对 App Server 返回的来源与查询前后账号。自定义启动环境、同机多登录来源或其他设备不保证与目标窗口自动一致，请在详情中核对实际读取的账号与目录；检测到来源变化时不展示旧结果。未登录时先在 Codex 中登录，不要把另一台电脑的认证文件复制进 CAR。

百分比是对应窗口的剩余量，不是本次聊天或本机独立消耗。周期按响应决定；没有窗口数据时显示未知，不伪造 0% 或 100%。刷新失败仅在已确认同一账号时保留标明“旧数据”的快照；重置到点也需实际刷新，不会直接把进度条填满。第二台实体电脑的额度读取已由用户确认验收，见 [验证记录](validation.md)；该结果不等于真实暂停/输入链路通过。

语音模式的蓝色圆形小叉属于辅助识别形态，只观察、不自动关闭语音。有主按钮时优先使用主按钮，小叉不会把单个恢复按钮变成需要选择的多个候选。

## 监测与点击规则

后台以新帧事件驱动，普通前台检测与后台兜底约每 3 秒一次；问答状态约每 2 秒检查一次。右三角形连续稳定出现且输入空闲窗口满足后，点击前独立核对一次；复查期间有输入取消本次点击。恢复尝试至少间隔 5 秒，白色运行方块用于确认成功。

普通自动恢复中，发送箭头、声波和方块只观察；额度控制只有在本次拥有的暂停事务内才可能停止或补发，问答始终等待用户。临时捕获失败、拖动窗口、无法识别和未确认方块时持续监测。点击“暂停”停止监测和点击，保留目标和选项；点击“继续监测”恢复。暂停期间修改选项不会自动继续。关闭窗口退出工具。

## 状态与活动记录

主窗口显示监测状态、真实局部预览、目标窗口、监测方式、自动恢复开关、本轮已确认恢复次数和可滚动的本轮时间戳进度。“完整记录”显示连接、暂停、恢复、需要人工处理及故障等重要事件，首页约每 10 秒补一条简短检查进度，保留本次运行的历史，可通过滚轮或滚动条向上翻阅；处于底部时跟随新进度，翻阅旧记录时保持当前位置。完整活动记录不追加这些周期性进度。

正常静止保留最近识别结果，不因 5 秒没有新帧而报警或因 15 秒静止重建帧池。收到系统新帧后触发处理，兜底降为 3 秒；仅在恢复按钮出现且允许自动恢复时，短暂以约 200ms 复查稳定性，图标稳定观察与 1.5 秒输入空闲并行计算。点击前会独立获取新画面，原始内容时间超过 5 秒的画面不能授权点击；点击后的新方块帧才计为确认成功。

1.1.14 首页预览旁只显示一个 `HH:mm:ss`，对应当前实际展示的预览内容；检查缓存或暂停保留预览不会将时间伪装成新画面，无画面留空、未知时间显示破折号。画面和检查两种时间仍在诊断中保留。首页按钮预览按蓝色圆形边界加少量边缘裁剪；问答模式显示较宽的提示与操作区域，点击可放大，不自动保存问答图。

“设置 → 诊断工具”显示按钮局部图、识别分数和捕获统计，并提供“打开日志”。日志位于 `%LOCALAPPDATA%\CodexAutoResume\logs`，每类日志保留约 2 MiB 当前文件和一个历史文件；诊断日志每 10 秒记录一次。详见 [日志说明](monitoring-logs.md)。

## 自动更新

启动约 5 秒后后台检查 GitHub 最新正式版，运行中每 6 小时再检查一次，也可在“设置 → 帮助与更新”手动检查。自动检查可在常规设置关闭。没有更新或后台网络检查失败时不弹窗。

发现新版后显示版本和更新内容，提供“立即更新 / 稍后 / 跳过此版本”。同一版本每次运行至多自动提醒一次；跳过会记住，手动检查仍可查看。

立即更新后自动下载并校验 SHA256、产品、版本及 x64 EXE。下载期间继续监测；准备成功后暂停并退出，由临时更新助手替换原路径 EXE、启动新版。替换失败保留旧版；新版未完成启动确认则尝试恢复并启动旧版。旧版备份无法安全回退时保留在原目录，错误详情保留在用户目录的 updates 子目录。

更新使用普通用户权限。当前目录不可写或 EXE 只读时会提示失败，保留当前版本，可移到可写目录或手动更新。日常分发仍为一个 EXE。没有更新功能的旧版需要手动下载本版一次。

## 自检与演示

以下功能位于“设置 → 诊断工具”。

| 功能 | 用途 |
|---|---|
| 本机自检 / F2 | 检查系统接口、内嵌资源、任务栏身份和用户数据目录 |
| 后台自测 / F4 | 用工具自己的按钮与遮挡窗口验证后台恢复路径 |
| 打开演示 | 测试按钮状态、双区域和位置变化 |
| 保存按钮图 | 主动保存上一帧按钮区域，用于识别排查 |

后台自测期间暂勿移动鼠标或切换窗口。可关闭遮挡窗口或使用停止快捷键取消。自测暂停日常监测，完成后点“继续监测”恢复。

## 可选快捷键与备用标定

日常使用不需要快捷键。自动定位不适用时，可以手动标定：

| 功能 | 默认组合 |
|---|---|
| 连接当前前台 Codex，使用自动定位 | Ctrl+Alt+F8 |
| 鼠标放到按钮中心后手动标定 | Ctrl+Alt+F7 |
| 开始 / 暂停 | Ctrl+Alt+F9 |
| 停止 | Ctrl+Alt+F10 |

被占用时依次尝试 Ctrl+Alt+Shift、Ctrl+Shift，以主窗口显示为准。手动标定记录窗口内坐标，移动后跟随；改变窗口尺寸或 DPI 后重新标定。F8 可回到自动定位。区域选择没有默认选中项。

## 换电脑

只复制一个 EXE，放到任意可读取位置启动，程序目录可以只读。日志写入当前用户的 LocalAppData。图标识别不需要外部图片或开发环境；问答 OCR 需要相应的系统识别语言。

反馈问题时提供工具与 Codex 版本、Windows 版本、显示缩放、工作模式和复现步骤。详细排查见 [FAQ](troubleshooting.md)。

## 捕获对照与更新摘要

遮挡时怀疑状态停留，可在“设置 → 诊断工具 → 导出捕获对照”生成持久会话、独立会话及之后持久读取的本地图片、按钮区域和 comparison.txt。操作期间暂停日常监测，不发送点击，不激活 Codex；完成后恢复原监测状态，期间明确停止则保持停止。报告和完整窗口图可能含当前聊天内容，仅保存在本机日志目录，不自动上传。可在同样任务状态下分别遮挡、露出一部分和唤到前台后导出，帮助比较实际像素；新系统帧时间并不证明目标 UI 已重绘。

更新弹窗按所选语言展示最多五条更新摘要，已知问题单列，完整说明通过 GitHub 链接查看。正文不使用文本输入框，不默认选中；初始焦点与默认回车操作为“稍后”，Tab 可移到“立即更新”。检查结果会显示当前版本、线上正式版本及来源；开发版高于线上时明确说明。
