# CAR 界面重构方案

日期：2026-10-30  
基线：1.1.23  
状态：已在 1.1.24 实施，实际系统 DPI 和辅助技术继续验收

CAR 的首页应让用户直接看见当前状态、自动恢复开关和剩余额度。当前布局把核心信息与日志一起放进整页滚动区域，设置又把多种任务堆在“常规”长页中。本次重构以稳定的信息层级、内容分组和明确的滚动边界为主，覆盖首页、设置、记录、额度详情和辅助窗口。

用户已授权实施本方案，自动检查新版本由 6 小时改为 1 小时，首页、六类设置及辅助界面已重构。以下保留设计依据与验收要求；具体实现、任务编辑窗口的选择及验证边界见[1.1.24 实施记录](history/2026-10-30-v1.1.24-ui-refactor.md)。

## 现状与原因

### 首页滚动回归

用户两张截图展示了同一问题的两个位置：顶部可见时额度被挤出窗口；滚到额度时，标题、监测状态和暂停按钮被卷走。最近进度自身还有纵向滚动条，形成同方向的内外两层滚动。

对比 1.1.22 的 `37ad4a6` 与 1.1.23 的 `f4465e8`：旧首页根布局为 `Dock=Fill`；新版在 `MainUi.cs::InitializeCompactUi` 中改为 `Dock=Top + AutoSize`，再包进 `AutoScroll=true` 的 Panel。修复说明文字截断时，原先受窗口约束的仪表布局变成了内容驱动的长页面。

额度在两个版本中都通过 `UsageUi.cs::InitializeUsageFooter` 放在第六行，不能把这次问题简单描述为“新版移动了额度”。直接变化是它不再保证首屏可见。末行改为 AutoSize 后，内部 footer TableLayoutPanel 未启用 AutoSize 或指定合适的内容高度；本轮量测显示它实际占用 100 像素，额度和计数又在其中垂直居中，产生截图中的明显空隙。

本轮对正式 1.1.23 EXE 做了隔离布局量测：

| 项目 | 默认窗口 | 最小窗口 |
| --- | --- | --- |
| 主窗口客户区 | 560 × 500 | 520 × 491 |
| 首页内容高度 | 565 | 565 |
| 六行高度 | 44 / 116 / 80 / 77 / 112 / 100 | 同左 |
| 外层纵向滚动 | 出现，内容超高 65 | 出现，内容超高 74 |
| 额度所在末行 | Y=447，高 100，内容垂直居中 | 同左 |

这是 96 DPI、本机默认字体、未连接目标的量测，证明默认布局本身就能溢出；不以此推断用户截图的具体 DPI。截图补充了实际连接、持续监测和有额度数据时的表现。

### 设置的信息结构

`MainUi.cs::ShowSettings` 的“常规”依次加入语言、后台监测、自动检查更新、恢复范围、额度控制、定时恢复、一次性任务指令和高级定位。最小窗口中该页内容高 1470 像素，而滚动视口仅高 411 像素，约为 3.6 个视口。用户必须滚动才能知道有什么功能，关联设置也缺少明确边界。

设置先按独立 Form 创建，再变成 `TopLevel=false` 的嵌入窗体；它不再拥有原先设计时的窗口尺寸。1.1.23 已取消嵌入 Form 的最小宽度限制，但独立窗体参数与嵌入页面职责仍混在一起。首屏、诊断和辅助窗口也各自设置字体、留白、行高和按钮排列，缺少共同布局约束。

`WindowUi.ScrollContent / FitChildren / FitText` 把宽度逐层传入控件，能缓解裁切，但把复选框一律扩到可用整行宽度。在额度阈值这类“勾选项 + 数字 + 单位”的复合行中，会把原本相关的字段拆散。隔离量测中两条阈值 FlowLayout 行均高 66 像素，而普通按钮行高 39；这一机制需用专门的字段行替换，不能继续依靠统一放大或随意换行。

### 全界面审查

| 区域与实现 | 现有表现或结构问题 | 重构方向 |
| --- | --- | --- |
| 首页状态与采样图，`MainUi.cs` | 大产品名、状态图、监测状态、业务状态、采样说明与时间争夺上方空间；“方式”单独占一行 | 当前业务状态为第一层；监测方式和目标为第二层；采样作为次要详情 |
| 自动恢复与定时摘要，`MainUi.cs / ResumeSchedule.cs` | 开关、固定帮助、无计划提示长期占据三行 | 保留开关和短帮助；有效定时才增加摘要，完整规则在任务页 |

| 窗口及区域选择，`WindowPicker.cs / Selection.cs` | 独立尺寸与列表列宽；说明、预览、列表和动作各有自己的高度规则 | 顶部说明按内容增高，列表承担剩余空间，底部动作持续可见 |

## Apple 官方规范及在 CAR 中的应用

以下为 2026-10-30 查阅的 Apple Human Interface Guidelines。原则来自官方规范；页面结构、尺寸和实现选择是 CAR 的设计方案。

| 官方规范 | 采用的原则 | CAR 中的落点 |
| --- | --- | --- |
| [Layout](https://developer.apple.com/design/human-interface-guidelines/layout) | 按重要程度排序；对齐、分组；渐进展开；适应窗口和文字尺寸 | 首页先状态与动作，再额度与记录；详情进入对应页面 |
| [Scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views) | 滚动区域边界清晰；避免同方向嵌套滚动 | 首页取消整页滚动；设置每个内容页只有一个页面级滚动容器 |
| [Settings](https://developer.apple.com/design/human-interface-guidelines/settings) | 减少设置负担；低频通用选项进入设置；任务相关操作靠近任务；分类导航稳定且标识当前项 | 自动恢复留在首页；定时编辑独立；设置分类与当前页面持续可见 |
| [Typography](https://developer.apple.com/design/human-interface-guidelines/typography) | 字号、字重和颜色共同表达层级；保持易读；字体数量克制 | 统一文字角色；额度数字使用正文层级；不以缩字解决拥挤 |
| [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) | 支持系统偏好和辅助技术；信息不能只靠颜色；保证对比和可操作性 | 状态有文字；原生焦点、Tab 和读屏名称；高对比下仍可区分控件 |
| [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) | 清楚的动作标签；限制突出按钮数量；用样式表示优先级 | 每个任务只有一个主要动作，读入、返回和详情为次要动作 |
| [Windows](https://developer.apple.com/design/human-interface-guidelines/windows) | 适应窗口尺寸；控制新开窗口数量；保留系统窗口界面 | 保留 Windows 原生边框；首页、设置和记录继续共用主窗口 |

CAR 是 Windows WinForms 程序。这里采用 HIG 的信息组织与交互原则，字体、快捷键、窗口按钮、焦点和高对比行为遵循 Windows。macOS 的设置菜单、Command 快捷键、SF 字体及 Apple 平台材质不直接套用。视觉上以清楚的分区、适度留白和稳定控件为目标，不引入 Liquid Glass 仿制、自定义标题栏或整套新 UI 框架。

## 首页布局

### 信息与操作顺序

首页分为五个连续区域：页头、当前监测、自动恢复、额度、最近进度。目标与监测方式合并为当前监测区域的上下文；恢复次数归入最近进度标题行。额度位于最近进度之前，保证用户无需滚动寻找。

```text
原生 Windows 标题栏
┌──────────────────────────────────────────────────┐
│ 监测                                      设置   │
│                                                  │
│ ● 正在监测                          暂停监测      │
│ 等待操作                                         │
│ ChatGPT · 当前聊天                 后台监测       │
│                                                  │
│ ☑ 自动恢复                                       │
│ 检测到暂停后，空闲 1.5 秒自动继续                 │
│                                                  │
│ 额度剩余                                查看详情 │
│ 5 小时  27%  ━━━·····     本周  42%  ━━━━····    │
│                                                  │
│ 最近进度             本轮恢复 0 次       完整记录 │
│ 01:15:36  正在检查 · 等待操作                     │
│ 01:15:47  已检查 · 等待操作                       │
└──────────────────────────────────────────────────┘
```

这是信息线框，数字来自用户示例，不是实时额度。具体间距由实际字体和控件测量决定。

### 空间分配

以现有 560 × 500 客户区为默认设计基准，520 × 491 为最小窗口代表。默认高度预算为：上下内边距共 32、页头 32、状态 60、目标上下文 40、自动恢复 44、额度 64、区域间距共 60，最近进度使用余下约 68 像素。实际实现按内容测量，不把这组预算复制成全部固定高度。

正常桌面字体下，这两个代表尺寸均不出现首页外层滚动条，状态、暂停、自动恢复和两种额度同时可见。最近进度允许展示 2–3 行；窗口增高时优先增加进度区。不能给额度容器保留一个未定义的 100 像素默认高度。

按可用空间依次降级：

1. 长目标标题单行省略，并提供可聚焦的详情入口；完整名称可复制，不只靠悬浮提示。
2. 额度条可缩短；仍不够宽时将两个额度窗口堆成两行，保留窗口名、百分比和数据是否过期。
3. 放大字体或极矮工作区时，先缩减最近进度为一条摘要与“完整记录”，再把采样说明、次要帮助和详细目标信息收进详情。
4. 仍受限时使用仅含状态、暂停、自动恢复、额度数值及详情入口的紧凑首页；不为塞进所有日志而裁掉关键操作。最小尺寸按系统缩放及工作区约束重新计算。

重构后的根布局 `Dock=Fill`，用 AutoSize 内容行与唯一的弹性进度行分配高度；不再用 AutoSize 根表格推高整页。字号、语言或 DPI 改变后重新测量字段和按钮，而不是单纯隐藏滚动条。

### 状态与反馈

“正在监测”描述 CAR 的状态，“等待操作 / 正在运行 / 检测到暂停 / 等待你的回答 / 正在恢复”描述目标任务；两者保留为不同层级。暂停按钮明确写“暂停监测”，自动恢复开关明确写“自动恢复”，避免两个“暂停”指代不清。

主状态保持简洁，解释文字紧邻当前原因。最近一次可核验状态的时间放在详情或状态辅助行；采样图可以点击查看，但不再让它决定整块状态区的列宽。问答区域大预览进入详情，首页保留“等待你的回答”及查看入口。

正常运行、未连接、用户暂停、等待输入让行、额度不足、问答阻断、正在重连和恢复结果不明，都用同一结构呈现。颜色只作辅助，文字始终说明状态。无目标时显示“正在寻找 Codex”与选择入口，不留一个空白缩略图框。

审核 `FriendlyStatus` 的映射：例如不能把所有包含“最小化”的内部消息统一解释为“还原 Codex 后自动继续”；可核验后台接口仍可工作时，界面必须按实际阻断原因描述。此项只调整呈现，行为判断仍来自原有状态逻辑。

### 额度与进度

额度区域使用正文可读字号和明确的详情动作。有效、加载中、未登录、不可用、无额度窗口、旧数据分别有文字；保留最近成功读取时间。失败后的旧额度不能继续只显示成正常绿色数字，未知也不能画成 0%。进度条只辅助数值，不只靠颜色表达剩余。

最近进度在默认紧凑首页展示摘要，不承担长日志浏览。重复的同状态心跳可以在摘要里合并为最近时间或“已持续监测”，原始完整活动记录仍保留，不能丢失错误、用户动作、恢复尝试和结果。不改变日志采集频率或恢复判断。若显示多行，只有该区域自身可滚动；不嵌套在整页滚动中。

## 设置布局与保存语义

### 页面导航

继续在主窗口打开设置，顶部固定“返回监测”、页面标题和紧凑的当前监测状态及暂停动作。主窗口尺寸不会因打开某个设置页突然增大；首次打开进入常规，后续记住最近分类和该分类的阅读位置。

默认窄窗口使用带“设置分类”标签的单个分类下拉框；可用客户区宽度达到约 760 个逻辑像素时使用约 156 像素的左侧分类导航。分类与顺序保持相同，宽窄模式切换保留当前页和未保存内容。阈值按最终英文文字实测调整，不用多排 Tab 承载六个长标题。

| 分类 | 内容与顺序 | 滚动及主要动作 |
| --- | --- | --- |
| 常规 | 语言、快捷键说明；其他现有通用偏好按实际需要保留 | 短表单；语言即时生效 |
| 监测与恢复 | 前台/后台方式、能力短说明；恢复范围、读取和应用；高级定位折叠组 | 页面可滚动；“应用范围”为主要动作 |
| 额度 | 当前额度摘要与详情；额度控制开关；5 小时和周的阈值；继续指令 | 字段行完整；指令有显式保存 |
| 定时与任务 | 一次性恢复时间；一次性任务列表；新增和编辑任务 | 任务编辑独立子视图，保存后返回列表 |
| 诊断 | 当前连接与识别摘要；复制日志、导出诊断包；高级采集和工具 | 常用导出先可见；原始统计单独打开 |
| 关于与更新 | 当前版本、检查结果和检查按钮；自动检查与每小时说明；使用说明、许可证 | 检查状态就地显示；无更新不弹出额外流程 |

后台能力和 1.5 秒输入让行仍是现有规则；设置分类调整不改变默认偏好。更新开关从常规迁到关于与更新，首页“设置”入口保留，符合 Windows 工具的可发现性。

### 表单规则

每个组由标题、字段和必要的说明构成。短说明跟随相关字段，较长机制介绍使用“了解详情”；不把一段说明反复显示在首页、设置页和额度详情中。字段标签左对齐；普通宽度以标签列和编辑列组织，窄宽度将完整字段切换为标签在上、编辑在下。

阈值采用一个完整的字段行组件，例如“☑ 5 小时额度　剩余 ≤ [10] % 时暂停”。窄宽度可以在阈值编辑器之前换行，但不把数字和“% 时暂停”拆为无关联的碎片。复选框只占自己需要的宽度；帮助文字按组宽度换行。

额度控制未启用时，下属阈值禁用并显示原因；不开启新的默认策略。文本编辑、读取项目列表、应用恢复范围和保存任务是不同动作，不能用一个全局“保存”暗示它们等价。

| 操作 | 生效方式 | 未完成或失败时的呈现 |
| --- | --- | --- |
| 语言、监测方式、更新开关 | 沿用即时生效并保存 | 保存失败就地显示；状态来自实际偏好 |
| 额度开关和阈值 | 沿用现有即时变更及旧额度事务取消规则 | 明示影响；不能因重建页面误触设置变更 |
| 额度继续指令 | 编辑缓冲区，点“保存指令”才提交变更 | 未保存标识；离开时保存、放弃或取消离开 |
| 恢复范围 | 读取候选，选择，再显式“应用范围” | 保留当前已应用范围，另示未应用选择 |
| 一次性恢复 | 选择时间后显式设定或取消 | 成功后显示完整日期、时间与生效状态 |
| 一次性任务 | 新建或编辑视图中显式保存并绑定 | 绑定失败保留编辑文本和原因，不显示为已保存 |

继续指令改为显式保存是本方案建议，需在实施时把编辑状态与业务提交分开。已保存值变化仍调用原有取消/停用规则；不能因为是 UI 重构而绕过防止意外继续的保护。

### 滚动边界

每个设置内容页最多一个页面级纵向滚动容器，导航、返回和全局暂停留在其外部。短页无需人为预留滚动条宽度；出现实际溢出后统一由布局宿主计算内容宽度，避免反复扣除 `VerticalScrollBarWidth` 导致窄列。

多行指令编辑器、任务列表和原始文本属于可滚动内容控件。尽量让任务列表和编辑器各占独立子视图，避免外层长页再包两个长滚动框。编辑器自身滚动是保留长指令编辑能力的取舍：键盘可退出，触及边界的滚轮转交外层，不能让用户被困在内层。不得把整个复合输入行交给通用 FlowLayout 自动拆分。

## 记录与辅助窗口

| 页面或窗口 | 推荐结构 | 需要保留的行为 |
| --- | --- | --- |
| 完整记录 | 固定返回/标题、恢复与全部活动筛选、可伸缩日志区、复制或导出入口 | 原始完整时间戳；不同筛选分别保存横向/纵向位置与选择；阅读旧记录不被追加拉到底 |
| 额度详情 | 顶部两种额度及重置时间；账号与更新时间；可展开来源路径；底部刷新 | 读本机当前登录；换目标或来源时清空旧账号；刷新中禁重复请求 |
| 更新提示 | 标题和版本、可滚动说明、固定动作区 | “稍后”为初始焦点与安全默认；立即更新、稍后、跳过各自语义不变 |
| 更新进度 | 简短阶段、进度、可复制失败详情 | 不改变下载、校验、交接、回退和旧文件保留规则 |
| 目标窗口选择 | 顶部短说明、可伸缩列表、底部确认和取消 | 未选定不启用确认；长标题有全文；选中不自动开始恢复 |
| 区域选择 | 说明、可缩放总览、候选列表、固定动作区 | 未确认区域不授权点击；列宽按内容及可用宽度分配 |
| 图片详情 | 图片缩放、来源与时间说明、关闭 | 明确区分状态示意与实际采样，不以示意冒充截图 |
| 帮助、自检、错误与许可证 | 简短信息用原生对话框；长输出用可复制只读正文与固定关闭按钮 | 焦点、Esc、所有者和工作区边界正常；技术错误不塞入首页主状态 |

辅助窗口打开和关闭不应改变监测开关或目标绑定。只在任务确实需要确认时使用模态窗口；额度详情等只读内容保持非模态。执行完毕的临时窗口、刷新计时器和图片及时释放。

## 视觉与无障碍规则

以下为 CAR 的初始设计参数，均以 96 DPI 逻辑尺寸描述，实施时随系统缩放，不是 Apple 对 Windows 的尺寸规定。

| 项目 | 方案 |
| --- | --- |
| 字体 | 使用 Windows 可用的界面字体及中文回退；沿用现有 Microsoft YaHei UI 也可，先统一文字角色 |
| 正文与数值 | 基准约 10–11pt；额度百分比使用正文或更大字号，不能继续靠 8pt 弱化 |
| 层级 | 页面标题约 13–14pt；主状态约 12–14pt 半粗/粗；正文常规；辅助说明略弱但仍易读 |
| 间距 | 4 / 8 / 12 / 16 / 24 的间距刻度；外边距 16–24；相关字段 8；组间 16–24 |
| 控件 | 常用按钮基准高约 32，宽度按文字测量；焦点和点击区域同时满足，触屏场景再增大 |
| 分区 | 浅色或系统背景、少量分隔线；优先用留白分组，不给每一行加卡片和阴影 |
| 颜色 | 语义化正文、辅助、边界、强调、成功、注意、错误；使用系统色及高对比回退 |
| 对比 | 普通文字以至少 4.5:1 为目标；较大文字至少 3:1；同时核对可见焦点与禁用状态 |
| 操作 | 每个任务一个明确主要按钮；链接用于导航和详情，按钮用于执行动作 |

Tab 顺序随视觉顺序。Space 操作复选框，Enter 只触发当前任务明确的提交行为；打开设置、切换分类或语言不得触发恢复/发送。Esc 优先关闭子视图或返回；有未保存指令时先处理编辑状态。状态与额度提供可读名称和文字值，读屏不能只能读出一个没有内容的自绘 Button。频繁心跳不反复抢焦点或逐条读出；需要用户处理的状态变化才发适度提示。

尊重 Windows 高对比、系统缩放和减少动画偏好。主题支持范围与当前产品一致；本次不为外观额外引入全套主题设置。高 DPI 验收必须涉及真实系统缩放与跨屏移动，不能把放大 Font 的结果写成系统 DPI 通过。

## 实施结构

采用现有 WinForms 与便携分发方式。新增共用的布局与字段组件，逐页替换任意 FlowLayout 堆叠；不把本次改动扩展成框架迁移。

1. 在共用界面层建立间距、文字角色、语义颜色、字段行、分组、页面宿主和对话框动作栏。统一负责内容宽度与 DPI 换算，避免各页自行猜测滚动条宽度。
2. `MainUi.cs::InitializeCompactUi` 调整为窗口约束下的根布局；`UsageUi.cs::InitializeUsageFooter` 拆为额度区，不再由恢复次数决定剩余宽度。问答预览与技术细节退出主状态列。
3. 将 `ShowSettings` 拆成页面宿主与各分类构建函数；嵌入内容用 UserControl/Panel，不再创建后去边框的 Form。原有 `AddScopeSettings / AddQuotaSettings / AddScheduleSettings / AddTimedInstructions` 逐项迁移到对应页。
4. 状态来自现有业务对象，由统一渲染方法更新控件；每次构建或语言变更使用加载保护，不能因 `CheckedChanged / SelectedIndexChanged / TextChanged` 意外调用取消计划、改目标或发送。
5. 原有字段控件被多个业务回调直接引用，迁移时逐个核对生命周期。显式保存指令有独立编辑缓冲；关闭设置只清理页面资源，后台监测与其他窗口的状态不会继续写向已释放控件。
6. 改造记录和辅助窗口，复用共用标题/动作区；保留 `ProgressHistory` 已修复的左侧原点、选择及阅读位置语义。

UI 改造不改变 1.5 秒输入让行、不引入普通恢复草稿检查、不扩大目标授权，也不把只读绑定当作动作成功。持续监测、额度与定时事务、恢复确认和更新助手的原有边界测试继续保留。

## 更新检查改为每小时

该需求单独实施，避免必须等完整 UI 重构才落地。

- `MainUi.cs::CheckUpdatesAsync` 的 `DateTime.UtcNow.AddHours(6)` 改为统一的 1 小时间隔定义，成功或失败后的下一次自动检查仍按该间隔安排。
- 保留启动约 5 秒后的首次检查；关闭自动检查时不请求；开启时沿用近期检查行为；检查中、安装中或诊断时的防重入/让行仍有效。
- 手动检查沿用现有入口与调度语义，不新增复杂的间隔选择设置；同版本提示去重、跳过版本与网络失败静默继续保留。
- 同步更新 `MainUi.cs` 关于页、`UiText.cs` 英文、`README.md`、`README.en.md`、`docs/user-guide.md` 的当前说明，历史发布记录不改写。
- 用可控时间核对到期、未到期、关闭、手动检查和请求并发的代表情况，不等待真实一小时；发布流程沿用现有 1.1.x 规则。
