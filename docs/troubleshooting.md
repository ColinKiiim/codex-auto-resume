# Codex 频繁 at capacity、任务暂停与自动恢复 FAQ

[返回首页](../README.md) · [English](troubleshooting.en.md) · [使用指南](user-guide.md)

本页面面向在 Windows Codex 桌面应用中遇到 `at capacity`、`atcapacity`、`Selected model is at capacity`，或者任务暂停后需要反复点继续的用户。CodexAutoResume 用于自动操作可识别的恢复按钮。

## Codex 总是提示 at capacity，怎么解决？

先查看完整提示和当前任务状态。仅凭“at capacity”几个字，不能判断一次中断的全部原因。可以按以下顺序排查：

1. 查看 OpenAI 官方文档中的[服务状态入口](https://developers.openai.com/api/docs/guides/error-codes)，确认是否有服务异常。
2. 如果客户端明确提示用量上限或重置时间，查看自己的用量页面；具体额度和恢复时间以账号显示为准。[官方用量说明](https://learn.chatgpt.com/docs/pricing)。
3. 如果提示建议切换模型，可以根据客户端提供的可用选项选择，再重试。持续失败时保留报错时间、版本和复现步骤，按[官方排查与反馈说明](https://learn.chatgpt.com/docs/reference/troubleshooting)反馈。
4. 如果任务仍在原聊天中，并且右下角出现向右三角形恢复按钮，可启用 CodexAutoResume，减少反复手动点击。

工具恢复的是按钮操作，不会改变服务容量或账号权限。它也不会把“按钮可点”等同于下一次请求一定成功。

## at capacity 和使用额度耗尽一样吗？

排查时应分开看。服务可用性、账号用量、网络连接和等待用户操作可能导致不同的中断；以完整提示和账号用量为依据。

OpenAI 的 [API 错误说明](https://developers.openai.com/api/docs/guides/error-codes)区分模型临时过载与配额/计费相关错误。这是 API 的错误分类，不能直接当作每个桌面弹窗的确定诊断。对于 Codex 桌面应用，本工具只观察图形，不访问错误响应或账号额度。

## 如何让 Codex 暂停后自动继续，不用一直守着？

从本仓库 Releases 下载 Windows x64 EXE，启动后核对目标窗口和图标，打开“自动恢复”。工具自动定位恢复按钮，不需要每次按快捷键。

当右三角形连续稳定出现时，它在点击前再次取样核对，再执行一次恢复。随后看白色方块确认是否已开始运行。重试至少间隔 5 秒；服务仍不可用时，后续恢复仍可能失败。

适用条件是**当前版本可识别的 Codex 恢复按钮实际出现在目标窗口内**。只有报错文字、其他样式的重试按钮或 CLI 文本输出时，不会凭文字自动操作。

## 白色方块一直不变，是软件没继续识别吗？

先看主窗口是否显示“正在监测”。正常静止保留最近观察，界面不会反复刷心跳；技术统计位于“设置 → 诊断工具”，诊断日志每 10 秒记录一次。

“读取次数增加”与“系统提供了新画面”是两件事。静止本身不会触发警告或定时重建；准备点击时独立获取新帧，点击后的新方块帧才用于确认。[日志说明](monitoring-logs.md)解释了这些字段。

## Codex 被其他窗口完全盖住，还能恢复吗？

可在设置中启用“后台监测”。它获取目标窗口画面，再向目标窗口发送后台消息，不移动系统鼠标。Codex 需要保持未最小化，并能提供更新画面、接受后台消息。

先运行 F4 /“后台自测”验证这台电脑的捕获和输入路径，再在自己的 Codex 暂停场景核对实际行为。测试期间保持鼠标和前台窗口不动。[后台模式说明](background-mode.md)。

## 最小化、锁屏、睡眠时能工作吗？

最小化时等待窗口还原。当前版本没有把锁屏或休眠后的自动操作作为支持场景；睡眠期间程序无法持续执行。后台模式的“完全遮挡”指另一个普通窗口覆盖 Codex。

## 为什么出现黄色边框？

这是 Windows 窗口捕获的系统指示。程序复用捕获会话来减少反复启停导致的闪烁；窗口重建或重新连接时仍可能变化。

## 引用编号会被误认成恢复按钮吗？

1.1.7 起，自动候选只包含识别成功的按钮状态，蓝色数字引用等未知图形被排除；声波识别还核对竖条形状。数字 0–99 的 1,800 组字体、字重、缩放组合已作为负样本验证。

真正出现多个按钮候选时，程序继续扫描；恢复单候选后回到原来的工作模式。也可以主动选择区域。

## 会把发送箭头、停止方块、问答面板一起点掉吗？

不会按这些状态执行恢复点击。发送箭头、语音图标、白色运行方块都只观察；问答面板等待用户回答。程序不会自动选择答案、跳过问题或提交回答，也不会批准权限请求。

## 需要 OpenAI API Key、登录账号或联网识图吗？

不需要。按钮识别、窗口捕获和问答 OCR 在本机处理。工具不接收账号密码，不代理 Codex 的请求。Codex 自身仍按原来的账号、网络与服务条件工作。

## 可以在另一台电脑直接运行吗？

复制一个 EXE 到 Windows 10 1903+ / Windows 11 x64 即可尝试运行，使用系统 .NET Framework、WinRT 和 D3D11。无需复制源码或样本图片。问答面板识别需要对应 Windows OCR 语言。[本机迁移检查记录](migration-audit.md)。

## 是否支持 Codex CLI、浏览器版或其他系统？

当前支持范围是 Windows x64 的 Codex 桌面窗口。CLI 和 API 程序应使用其自身的重试机制；API 调用的等待间隔与错误处理参考[官方错误说明](https://developers.openai.com/api/docs/guides/error-codes)。本项目没有提供 CLI 包装器、浏览器插件或 macOS/Linux 版本。

## 问题应该向哪里反馈？

图标识别、自动定位、后台捕获和本工具日志的问题，在本仓库 Issues 提交；模型容量、账号额度或客户端服务错误按 OpenAI 官方渠道反馈。提交方法见 [CONTRIBUTING](../CONTRIBUTING.md)。
