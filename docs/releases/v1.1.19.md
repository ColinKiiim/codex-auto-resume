# CodexAutoResume v1.1.19

2026-10-29

## 修复

- 完全遮挡时，旧的运行方块截图可能不断带着新系统时间返回，导致暂停漏检。后台监测现在优先核验原窗口、聊天和输入区，直接读取当前按钮状态并确认恢复结果，减少对目标后台绘制的依赖
- 排除标题栏“还原”等无关控件；只允许已绑定输入区内的唯一动作按钮参与操作。聊天变化后重新建立状态，不能用另一个聊天的运行状态确认之前的恢复
- 遮挡时的 UIA 按钮通过精确控件绑定的后台窗口消息操作，避免直接 Invoke 抢焦点

## 新增

- 目标已有且可独立核验的本机 CDP 接口时，支持保持最小化的暂停、恢复、中文多行输入和提交，以及项目展开、聊天切换。额度、定时恢复、一次性任务和范围轮询使用相同的目标与输入保护
- 首页区分“后台控件状态”和实际采样图；诊断记录状态来源、页面/聊天绑定摘要、按钮归属、祖先链及支持模式。开启详细诊断后，未最小化时约每 15 秒另存窗口原始帧用于对照；对照截图不授权点击

## 支持边界

最小化操作需要目标已经开放、归属与聊天均可核验的接口。不会自动开启调试、重启或还原目标；接口不可用、目标不明确或结果不明时等待。图像路径仍禁止最小化点击，最小化时不信任可能缓存的 UIA 按钮状态。继续保留连续 1.5 秒鼠标/键盘空闲、草稿/问答保护和消息不明不重发。

已通过自有 Chromium/Electron 的完全遮挡、最小化和安全边界验证；本机真实 Codex 完成了多页面绑定的只读检查。用户故障设备的完全遮挡/最小化结果，以及真实后台发送和服务端额度重置后的完整流程仍待验收，不能以夹具代替。见[实现与验证记录](../history/2026-10-29-v1.1.19-background-controls.md)。

## Fixed

- Background monitoring now prefers independently bound composer controls over captured pixels. This addresses missed pauses when a fully covered target keeps supplying an old running-square image with fresh system timestamps
- Only the original composer's unique action is eligible. Window Restore controls are excluded, and another conversation cannot confirm a previous action
- Covered UIA actions use messages to the freshly bound render widget instead of an Invoke call that can steal foreground focus

## Added

- An existing, ownership-verified CDP endpoint enables pause/resume, multiline text submission, project expansion and chat switching while the target remains minimized. Quota control, scheduling and scoped tasks retain their safety conditions
- Control-state previews are clearly distinguished from captured images. Diagnostics include control provenance, binding hashes and supported patterns; opt-in image comparisons run about every 15 seconds on non-minimized targets and never authorize actions

Minimized operation requires a verifiable existing endpoint. CAR does not enable debugging, restart or restore the target. Unavailable or ambiguous controls wait; cached minimized UIA labels and minimized image clicks are rejected. The 1.5-second input-idle rule and draft/question/uncertain-submission protections remain. Owned Chromium/Electron checks passed; the affected PC, real-app background submission and real server-side quota reset still require acceptance.
