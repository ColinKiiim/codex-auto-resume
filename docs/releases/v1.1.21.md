# CodexAutoResume v1.1.21

2026-10-29

## 修复

- 更新助手使用同一内核进程句柄核对创建时间、完整路径并等待原程序退出，避免读取正在退出的进程主模块而触发 ReadProcessMemory / WriteProcessMemory 部分完成错误。进程身份或路径不匹配时仍拒绝替换
- 原程序收到助手身份和就绪确认后才关闭；助手来自已经校验的新版本文件，使后续版本可以使用随版本提供的更新器修复
- 更新失败时重新校验当前 EXE，分别显示原版本、新版本仍在或无法核验；回退失败保留备份，不再统一声称已恢复，也不把失败的新程序再次启动为“恢复成功”

## 新增

- 更新目录新增 outcome.json，记录阶段、异常类型/原生错误码、回退错误及文件校验结果；failure.txt 保留异常详情。简要结果进入诊断日志，可随近 30 分钟复制/导出，不自动上传

## 从旧版升级

1.1.20 及以前的自动更新由旧助手执行，发布新版本无法改写已经运行的旧助手。若仍出现相同错误，请关闭旧 CAR，手动下载本版 EXE 后放回原位置替换一次。设置和日志保存在 `%LocalAppData%\CodexAutoResume`，无需删除。无需管理员权限，也不建议通过提升权限绕过进程身份检查。

本版完成自有进程的交接等待、原进程先退出、正常重启、新版启动失败回退、回退失败及助手拒绝检查。另一电脑的具体失败阶段与原版本是否恢复，仍需那台电脑的任务记录/文件核验，未将截图提示当作恢复成功证据。

## Fixed

- The updater verifies process creation time and full image path, then waits using one kernel handle instead of enumerating an exiting process's main module. Identity/path mismatches still block replacement
- The original app waits for verified helper readiness before closing. Future updates use the already verified candidate's helper implementation
- Failure messages distinguish verified old bytes, remaining new bytes and an unknown destination. Failed rollback retains the backup and does not relaunch failed new bytes as a restored app

## Added

- Local outcome.json records stages, native error codes, rollback errors and file verification; failure.txt retains details. A concise result enters recent diagnostic log copy/export, without automatic uploads

Older releases still run their old helper. If automatic upgrading fails again, close CAR and manually replace its EXE with this release once; settings/logs under `%LocalAppData%\CodexAutoResume` remain. Owned-process tests passed; the affected computer's actual failure and recovery status remain unverified.
