# CodexAutoResume v1.1.17

发布日期：2026-10-27（UTC+8）

## 中文

### 新增

- 指定项目或聊天作为恢复范围；项目范围按聊天轮询，动作前重新核对侧栏当前项、工具栏与文档。原生导航需要时先请求窗口激活，再投递一次切换；结果不明时停止动作，重启后需重新确认范围
- 多个一次性任务：分别保存时间、目标、独立指令与状态，到点后可切回绑定聊天，等待空框、有效账号、已启用额度及输入安全条件。相同聊天按到期顺序排队，结果不明会阻止该目标后续任务，重启需重新绑定，不自动重放
- 左下角恢复次数可悬浮预览最近 24 小时最多四条记录，点击查看全部已保存的恢复记录；只有已确认的真实恢复进入历史，演示与点击尝试不计入

### 变更

- 设置与记录在主窗口内打开，保留返回和暂停监测入口
- 按系统权限尝试无边框窗口捕获，覆盖持续会话、独立复核和重连；权限或接口不可用时保留正常捕获，诊断显示实际状态

### 修复

- 重开设置时回填已保存的恢复时间，标明未保存修改，并持续区分未启用执行、等待到点、输入/额度阻塞及操作待确认
- 适配 Codex 辅助树中的真实空框占位结构、焦点异步生效、写入/发送后输入控件重建和多行用户消息确认；保留草稿、账号、原聊天及不明结果不重试保护
- 确认消息送达时兼容很快完成的问候回复，不要求恰好捕获短暂的运行帧

### 验证范围与限制

本机真实 Codex 已完成隔离额度驱动的暂停、低额度保持、额度与时间共同放行后的恢复；真实中文多行写入、消息送达和草稿保护已验证。真实项目切换与返回、两条独立定时指令也已验证。隔离额度不是服务器真实重置。UIA 后台写入在本机不可用，已验证焦点后备；现有 CDP 端口环境与另一台电脑的无边框表现仍需对应环境验收。原生导航在部分后台状态下曾出现确认超时，超时会关闭该次动作并要求重新确认，而不会重复投递。其他软件同时要求捕获边框时，CAR 无法独自隐藏系统边框。

## English

### Added

- Select a project or chat as the recovery scope. Project polling verifies the current sidebar item, toolbar and document before actions. Native navigation may request activation before a single switch; uncertain outcomes stop actions. Confirm the scope again after restart
- Multiple one-time instructions with separate deadlines, targets, prompts and states. Due tasks can return to the bound chat and wait for safe input, account and enabled quota conditions. Tasks for one chat retain deadline order; uncertain outcomes hold later tasks for that target. Rebind after restart; no automatic replay
- Hover over the recovery counter for up to four records from the last 24 hours, or click to browse all saved recoveries. Only confirmed real recoveries enter history; demos and click attempts do not

### Changed

- Settings and records open inside the main window with Back and Pause controls
- Request system-authorized borderless capture for persistent sessions, independent checks and reconnects. Preserve capture when permission or APIs are unavailable and report the actual state in diagnostics

### Fixed

- Restore saved recovery times when settings reopen, mark unsaved edits, and distinguish disabled execution, pending deadlines, input/quota blocks and unconfirmed actions
- Handle Codex's raw placeholder structure, asynchronous focus, editor recreation after writing/submitting, and multiline user-message confirmation while preserving draft, account, conversation and no-retry safeguards
- Confirm delivered messages even when a short greeting completes before the transient running state is sampled

### Validation and limitations

Real Codex pause/hold/recovery passed on this PC with isolated quota values and a time gate. Chinese multiline input, delivered messages, draft preservation, project switching/return and two independent timed instructions were exercised. Isolated values do not establish a real server reset. UIA background writing is unavailable here and foreground fallback was verified. An existing-CDP environment and borderless behavior on the other PC still require their respective environments. Native navigation sometimes timed out in background states; uncertain outcomes stop actions rather than repeat navigation. CAR cannot suppress a system border requested by another capture client.
