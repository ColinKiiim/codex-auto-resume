# CodexAutoResume v1.1.23

2026-10-30

## 新增

- 当前聊天最新 capacity 错误的底部“重试”入口优先恢复；按钮仍挂载时可在阅读页面中部、窗口遮挡或最小化时操作，无需先滚到底部
- 日志区分恢复入口、具体阻断原因和后台绑定失败阶段

## 修复

- 内置浏览器、紧凑聊天、收起侧栏、多网页文档或无关编辑区不再使已确认的主聊天无法绑定
- 普通恢复不再被无关提交/跳过按钮、弹窗、附件、输入区按钮数量或固定祖先层数阻断，兼容 aria-labelledby 命名
- 使用稳定聊天和按钮节点身份复核；旧按钮不授权新动作，历史错误不覆盖最新任务，后台状态失效时清除旧示意图
- 可核验 CDP 侧栏支持同名聊天的独立身份，避免仅按标题拒绝目标；原生界面保留后备路径
- 最近进度固定从左侧显示完整时间戳，完整记录支持横向滚动与位置保留；主界面、设置、诊断和选择/更新窗口按内容换行、滚动，修正嵌入设置页最小宽度超出与长选项裁切

普通恢复继续不读取输入文字、不检查草稿。保持 1.5 秒输入空闲、已启用的额度/时间/范围设置和恢复确认。没有底部重试时保留普通恢复；同一次重试结果不明时等待新证据，不重复投递该失败按钮。

## Added

- Prefer the latest capacity error's bottom Retry action in the bound chat. Mounted buttons can be invoked while reading the middle, fully covered or minimized, without scrolling first
- Log the selected recovery action, specific blocking reason and binding failure stage

## Fixed

- Bind the main chat with embedded browsers, compact layouts, collapsed sidebars, multiple documents and unrelated editors
- Unrelated submit/skip buttons, dialogs and attachments no longer block ordinary recovery; remove arbitrary composer button-count and ancestor-depth limits and support aria-labelledby names
- Recheck stable chat and actual action-node identities, exclude historical failures and clear stale state previews when verification becomes unavailable
- Use stable CDP sidebar identities for same-title chats, retaining native-provider fallback
- Keep recent timestamps left aligned; provide horizontal full-history reading and preserve positions. Wrap and scroll content across the main window, settings, diagnostics and selection/update dialogs

Ordinary recovery never reads editor text or checks drafts. The 1.5-second input-idle window, enabled quota/time/scope settings and result confirmation remain. Composer recovery stays available without Retry. An uncertain retry waits for new evidence instead of resending the same failure button.
