# CodexAutoResume v1.1.16

发布日期：2026-10-26（UTC+8）

## 中文

### 新增

- 5h 与周额度分别设置暂停阈值，分别保存；旧配置自动沿用原共同阈值，任一启用周期不足即暂停，全部启用周期高于各自阈值才继续
- 一次性定时恢复：选择完整本地日期和时间，到点并满足额度、目标核验及输入空闲后才允许恢复；普通三角形和额度恢复使用同一时间限制，不主动暂停任务或定时发送新消息
- 首页显示定时状态；恢复成功后计划结束，停止监测、关闭自动恢复、切换目标或退出取消计划。修改/取消生效计划会关闭自动恢复；重启不重放，有计划时更新重启退回仅观察

### 变更

- 移除额度功能的中英文实验性标签；默认开关和安全检查保持，实际未验证项目继续如实记录
- 设置、额度详情、活动记录、预览和更新窗口在所属窗口附近居中，并限制在对应显示器的可用工作区内

### 修复

- 忽略定时计划创建前的旧暂停/运行证据，避免旧画面导致新计划提前结束

- 设置页使用独立滚动区域和完整内容高度，缩小窗口后仍能滚动至“手动标定”等末尾内容
- 修复无控制台的正式单 EXE 输入辅助进程设置输出编码时崩溃，改为直接向管道写 UTF-8；新增正式 GUI 程序的管道协议检查
- 适配当前商店版 Codex 的输入框与对话只读核验结构，综合文档标题、聊天工具栏及唯一侧栏项绑定；问答、重复标题、未知结构仍等待

### 已知限制

当前 Codex 已通过只读对话绑定与运行状态检查，带有待回答问题时拒绝操作。真实额度暂停、无三角形后的实际后台/焦点输入与发送全链路，以及原故障电脑遮挡专项仍待验收，不能将只读或自有窗体验证视为通过。当前未发现已有调试端口，不自动开启调试或重启 Codex。第二台实体电脑的额度读取已获用户确认通过。

## English

### Added

- Separate 5h and weekly pause thresholds with independent persistence and migration from the previous shared value; any selected low period pauses, and every selected period must exceed its own threshold to continue
- One-time recovery time using a full local date and time. Both ordinary and quota recovery wait for the time, quota, target and input checks; no scheduled stop or unrelated new messages
- Home-screen schedule status and single-use completion. Stopping monitoring, disabling Auto-resume, replacing targets or exiting cancels the plan. Replacing/canceling an active plan disables Auto-resume; restarts never replay it, and updates with an active plan return to observation mode

### Changed

- Remove experimental labels from the quota feature in both languages while retaining defaults, safeguards and factual validation limits
- Center auxiliary windows near their owner and clamp them to the owner's monitor work area

### Fixed

- Ignore pause/running evidence older than schedule creation so stale frames cannot consume a new recovery plan

- Independent settings viewport allows scrolling to the complete final calibration instructions, including at smaller window sizes
- Write UTF-8 directly to redirected pipes instead of setting console encoding in the production GUI executable's composer helper; add a production-executable protocol check
- Recognize the current Store Codex editor and bind its conversation through agreement between the document, chat toolbar and unique sidebar item; questions, duplicate titles and unknown structures remain blocked

### Known limitations

Read-only conversation binding and running-state inspection pass on the current Codex; a pending question correctly blocks actions. Real quota pause and background/foreground continuation submission, plus the original-device occlusion check, still require acceptance. Read-only and owned-fixture checks do not establish end-to-end compatibility. No existing debugging port was found; CAR does not enable debugging or restart Codex. The user confirmed current-login quota acceptance on a second physical PC.
