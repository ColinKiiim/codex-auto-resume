# CodexAutoResume v1.1.14

发布日期：2026-10-26（UTC+8）

## 中文

### 新增

- 设置中加入默认关闭的实验性额度控制：选择 5h、周或两者及阈值，任一所选额度不足即尝试暂停，全部恢复才继续；等待时画面每分钟采样
- 本轮额度恢复优先点击原对话的暂停三角形；消失时可尝试补发自定义继续指令，后台输入优先，必要时使用焦点输入后备。需核实原对话、空白输入框与有效额度，结果不明不重复发送
- 补充语音模式关闭小叉的辅助识别，仅观察，不抢占主按钮

### 改进

- 当前登录额度正常约每 10 秒查询，保持串行和失败退避；悬浮直接显示精确到秒的 5h / 周重置时间
- 额度摘要使用短暂点击动画，鼠标点击和关闭详情后不再残留焦点框；键盘导航保留焦点提示
- 采样图旁合并为单个时间戳，显示当前预览内容的时间，诊断仍保留画面与检查时间
- 中英文 README 覆盖额度不足等待、恢复后继续及官方全体提前重置场景：按新实际额度判断，不等旧倒计时；轮询存在延迟，周窗口起算由服务端决定

### 修复

- 处理新版 Codex 启动账号通知导致的额度读取中止：丢弃受影响批次，在同一会话最多完整重读一次，仍严格核验原账号与登录来源，持续变化仍拒绝

### 已知问题

实验性额度控制已接入，但真实 Codex 的暂停、后台输入及成功焦点后备尚未完成全链路验收。本机当前界面缺少可核实的已有调试接口/可用 UIA 编辑器与选中对话证据，功能可能保持等待；不会自动开启调试或重启 Codex。Windows 拒绝激活、已有草稿/附件/问答/语音或上下文不明时需人工处理。第二台实体电脑的额度读取及原遮挡故障专项复验仍未完成。此版本按用户明确指令发布，未把这些结果记为通过；额度控制默认关闭，普通三角形恢复保持原有路径。

## English

### Added

- Opt-in experimental quota control in Settings: choose 5h, weekly or both and a threshold; any selected low quota can trigger a pause, and all selected quotas must recover before continuation. Screen sampling drops to once a minute while waiting
- Prefer the original conversation's resume triangle after quota recovery; if it disappears, try a customizable continuation with background input first and foreground fallback when needed. Requires a verified original conversation, empty editor and valid usage; uncertain outcomes never trigger repeat submission
- Auxiliary voice-close cross recognition, observation only, without displacing primary button candidates

### Improved

- Query current-login quota about every 10 seconds normally, with serial requests and failure backoff; hover for precise 5h / weekly reset timestamps
- Brief click animation replaces persistent mouse-focus outlines after opening/closing usage details; keyboard navigation retains its focus indicator
- One preview-content timestamp replaces separate frame/check labels; diagnostics retain both
- Bilingual documentation covers quota waiting, continuation and an early reset for all users: use fresh actual quota instead of the old countdown. Polling has latency and the server controls weekly-window timing

### Fixed

- Handle startup account notifications by discarding the affected epoch and fully re-reading once on the same channel, while preserving original account/source checks and rejecting repeated changes

### Known issues

Experimental quota control is integrated but real Codex pause, background input and successful foreground fallback have not passed end-to-end acceptance. The current local UI exposes neither a verifiable existing debugging endpoint nor usable UIA editor/selected-conversation evidence, so actions may remain waiting. CAR never enables debugging or restarts Codex automatically. Activation denial, existing drafts/attachments/questions/voice mode and uncertain context require manual handling. Second-physical-PC quota compatibility and the original occlusion reproduction remain unverified. This version is published at the user's explicit request without claiming those checks passed. Quota control stays off by default; ordinary triangle recovery retains its existing path.
