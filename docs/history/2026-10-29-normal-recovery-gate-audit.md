# 普通恢复的额外条件审计 · 2026-10-29

用户质疑“单一网页文档、必须存在侧栏当前项”的限制，并要求查明是否还有其他不合理限制。本轮审查正式 1.1.22 的检测、绑定、动作、输入让行及可选额度/定时/范围路径；对代表性条件调用正式 EXE 的 observe 辅助进程复现，不修改程序或发布。

这些布局假设不是用户提出的使用要求。避免误点的目的不自动证明任何新增条件合理，尤其不能把发送消息时的防覆盖检查直接施加于普通恢复。

## 已确认的适配缺陷和过宽阻断

| 条件 | 源码与实际影响 | 本轮证据 | 初步处理 |
| --- | --- | --- | --- |
| 整个窗口只能有一个命名网页根，并依赖侧栏同名当前聊天项 | `ComposerWorker` 的 CodexDocument / BuildContext；CDP 也先调用该原生证明。正常多面板或隐藏侧栏导致绑定失败 | 上轮已在故障 MiniPC 直接确认，见[专项分析](2026-10-29-browser-panel-binding-failure.md) | 作用域限定到主聊天所属文档，以稳定对话身份支持正常布局变化 |
| 无关“提交/跳过”也阻止恢复 | UIA 在整个窗口找相关按钮；CDP 在整个 app 页面找可见启用按钮。返回 State=Resume、Safe=false，主循环停止普通恢复 | 同页面其他工具区域分别只增加“提交”“跳过”，正式版都得到 Observed / Resume / Safe=false | 判断真正属于当前任务的问答，不再用全窗口/页面同名词代替问答状态 |
| 附件、语音等检查复用于所有操作 | `AccessibleComposer.Inspect` 与 `DebugComposer.Operation` 将附件/对话框/问答/语音合并为 Safe；普通 observe/resume 同样受此字段影响 | 仅增加输入区附件标记与 Remove file 按钮，恢复按钮不变，正式版仍返回 Resume，但 Safe=false。语音 testid/名称分支为代码确认，未逐项复现 | 观察、普通恢复、发送消息分开定义必要条件；不能因有待发送内容便一概阻止点击明确的恢复入口 |
| 任意可见 dialog/alertdialog 视为整体不安全 | CDP 页面全局搜索，UIA 查窗口后代；没有区分当前问答、与恢复无关的查看器等 | 在其他工具区域增加普通 role=dialog，正式版仍识别 Resume，但 Safe=false | 判断实际遮断目标或当前任务交互的弹窗；必要的模态/问答保护保留，不能全按一个布尔值处理 |
| 必须依赖唯一、可编辑/可聚焦的特定编辑器 | 原生 SingleEditor 从全窗口找控件，依赖 ProseMirror、启用/焦点能力及固定中英文名称；CDP 从整个 app 页面要求唯一可见 ProseMirror。即使只是读暂停也先经过此处 | 其他工具区域增加一个 Notes 编辑器：CDP 失败并降级 UIA；再最小化则得到 minimized-state-requires-cdp，无法观察。可编辑/可聚焦条件本轮仅代码确认 | 将编辑器查找限定在主聊天，普通恢复不与“全页面只能有一个编辑器”或写入能力绑定 |
| 控件组按钮数至多 14；向上搜索层数固定 | UIA 上溯少于 7 层、每组按钮不超过 14；CDP 没有 form 时上溯少于 10 层且按钮不超过 14。是定位启发式，不是业务必要条件 | 去掉 form 包装，保留恢复按钮并添加 15 个普通工具按钮（共 16 个），正式版 Blocked / composer-container-unavailable。层数上限仅代码确认 | 使用可靠的主输入/操作区域结构和唯一动作目标，不用任意按钮数量代表区域身份；不能只把上限无限放大而混入其他区域 |
| 按钮名只有固定白名单，且 CDP 没有正确计算完整无障碍名称 | CDP 只读 aria-label / title / textContent，遗漏 aria-labelledby；两条路径只接受少量中英文固定名称 | 按钮用 aria-labelledby 指向“恢复”，浏览器 AX 明确得到名称“恢复”，CAR 却 Observed / Unknown / CDP；UIA 后备不会因 Unknown 自动启用 | 正确取得无障碍名称并结合目标控件身份/实际状态，不依赖某种标签写法或单个图标名字 |
| 聊天重名、多个同名 app 页面便拒绝部分路径 | 原生按标题匹配侧栏项数量；CDP 按标题要求唯一 app 页面；范围导航也会拒绝同名聊天 | 代码确认，未在本轮另建同名窗口复现。影响按后端/状态不同，不能写成所有同名聊天均完全不可用 | 用进程、原生窗口/文档、具体页面及稳定聊天身份区分；唯一动作目标仍须核验，“名字重复”本身不应代替身份判断 |

上述全局范围的 CDP 搜索限于连接的 app 页面，不是外部 Chrome 的所有标签；UIA 范围是目标窗口。自有样例说明这些条件能够触发，不能反推用户已经遇到每个例子。

## 正式版只读复现

本机独立 Electron/配置/自有 Store 布局路径，使用正式 1.1.22 observe 辅助进程。10 次聚焦断言通过（包含基线和无动作/前台/鼠标影响），不是 10 个真实应用环境：

1. 基线：Observed / Resume / Safe=true / CDP
2. 其他区域的“提交”：Observed / Resume / Safe=false
3. 其他区域的“跳过”：Observed / Resume / Safe=false
4. 附件：Observed / Resume / Safe=false
5. 其他区域的 dialog：Observed / Resume / Safe=false
6. aria-labelledby：浏览器正确识别“恢复”，CAR 返回 Unknown
7. 无 form、16 个按钮：Blocked / composer-container-unavailable
8. 其他区域多一个编辑器：Observed，但 CDP 失败，后备 UIA
9. 上述多编辑器样例最小化：Blocked / minimized-state-requires-cdp
10. 所有样例没有点击恢复按钮，前台/鼠标保持

脚本和原始结果只在 `.local/incidents/2026-10-29-browser-panel-binding/gate-audit.mjs` 与 `gate-audit-1793289010797/results.json`。没有操作故障机的恢复按钮，没有增加长期重复测试。

## 现有等待参数，不应隐瞒或混为使用限制

- `RecoveryWindow` 要求已观察到暂停持续至少 1.5 秒，同时鼠标/键盘至少空闲 1.5 秒且没有按键按住；两段等待可以重叠，并非简单相加。用户已明确要求保留输入让行，本轮不改。
- `ResumeGate` 还要求至少 4 次连续 Resume、跨度至少 900ms；距离上次尝试和上次确认恢复分别至少 5 秒。这些是已有的防抖/冷却实现参数，并非用户提出的额外操作要求，需要如实说明。
- 控件绑定失败有 5 秒重试间隔；此前成功建立过绑定后失败不使用旧图点击。这能放大定位缺陷的等待表现，但不能以重用旧图或取消身份核验代替修复。
- 普通 ResumeGate 在尝试 5 秒后解除 AwaitingRunning，满足条件时可再次尝试。不能将发送/导航“不明结果不自动重放”的策略笼统说成所有普通恢复都永久不重试；本轮不擅自改变现有恢复重试策略。

## 应保留但需作用域正确的条件

- 明确绑定实际目标进程、窗口、页面/聊天及唯一可用恢复控件，动作前重核验；不能点到另一聊天、网页登录按钮或“发送/停止”。
- 用户输入让行，以及自动恢复未开启/监测已暂停时不操作。
- 真正属于当前任务的问答等待，不替用户选择、跳过或提交；不能用其他区域的同名按钮来代替这个判断。
- 只在用户启用时应用额度、定时与指定范围。`QuotaAllowsNormal` 显式允许额度控制关闭时绕过额度条件；没有发现普通恢复暗中要求必须开启额度控制。具体发送/定时任务仍须按其已授权功能防止覆盖或误发送，不能反向套用到普通恢复。
- 最小化状态需要可核验的后台接口；无可靠接口时等待，属于当前技术能力边界。应修复错误的页面/编辑器作用域，使健康接口可用，不能承诺在缺乏任何可靠状态来源时按缓存坐标点击。
- 超时、候选上限等防挂死/资源边界与误把正常 UI 结构判为不支持是两类问题；本轮不删除进程身份校验、接口归属核验或超时回收。

## 修改方案与验收

先修已在故障机确认的文档/聊天身份绑定，结合主聊天作用域，避免逐条放宽全窗口条件又误选外部控件。随后拆开状态观察、普通恢复、真正写入/发送三类条件：恢复只判断与恢复动作相关的状态，发送才检查将被写入/提交的内容；不重新引入草稿门槛。将问答/模态判断限定到真实任务与目标，不按全局关键词阻断。

每次等待都应记录实际失败项（绑定、候选歧义、真实问答、输入活动、已启用计划/额度等），避免 Safe=false、Unknown 或“等待用户操作”掩盖具体原因。本文的“应保留”是对既有要求和必要目标核验的区分，不是新增业务限制。

验收至少包含本轮各已复现反例、紧凑聊天/内置浏览器、唯一目标与无关编辑器/工具按钮共存、中英文和合法无障碍命名、同名目标的身份区分，以及真实暂停恢复闭环；无关界面元素不得改变普通恢复是否允许。必要的目标核验、用户让行和真正问答保护同时回归。对等待/冷却或重试策略的改变必须作为可审阅的行为变更说明，不借清理结构限制擅自改变。

本轮完成的是审计、代表复现和方案，以上额外条件尚未清理，正式版仍为 1.1.22。
