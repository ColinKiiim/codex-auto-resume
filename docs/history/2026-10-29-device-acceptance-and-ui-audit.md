## 已复现的问题

### 日志左侧时间戳被横向偏移隐藏

- `MainUi.cs` 的 `RecentProgress` 始终拼接完整 `HH:mm:ss`，`UiText.Get` 也保留时间前缀；截图中左侧缺失不等于时间文本被删除。
- 主界面和完整记录共用 `ProgressHistory`，均设 `WordWrap=false`、只有纵向滚动条。`UpdateHistory`、`RestoreView`、`FollowAfterLayout` 处理纵向位置和选择，但不恢复或重置横向偏移。
- 隔离探针先追加长行，再用原生编辑框的横向滚动消息制造偏移：首字符 X 从 3 变为 -31。随后追加短行、调整宽度，所有行起点仍为 -31；渲染图只剩 `39 / 50 / 00` 等末尾时间，复现了用户截图的同类表现，底层文本仍完整。
- 边界：本次仅追加长行没有自动触发偏移。已证实“横向偏移保留导致时间不可见”，尚未证实故障机首次横移由自动跟随、键盘选择、焦点变化还是其他原生编辑行为触发，不能将某一候选原因写成已确定。

初步方案：最近进度在追加、替换、布局变化后保持左侧起点，纵向阅读位置与文本选择仍按原规则保留；完整记录提供可见的横向阅读入口并记住用户横向位置，避免没有横向滚动条却停在横移状态。长行全文继续在完整记录和日志导出可读。用长行→短行、选择/复制、滚动看旧行、切换记录及语言/尺寸变化核对，不能为复位横向而把正在阅读的旧记录强制拉到底部。

### 固定高度与实际文字/按钮高度不一致

另一个不依赖放大字体的已确认问题：设置原本按独立 Form 创建，保留 `MinimumSize=540×460`，随后改为 `TopLevel=false`、`Dock=Fill` 嵌入主窗口。主窗口最小外宽 536，在本机原生边框下客户区宽 520；探针测得设置页仍宽 540、父客户区宽 520，右侧超出 20 像素。独立渲染设置控件本身会漏掉父窗口的这层裁切，验收必须同时检查实际父客户区边界。

| 页面/控件 | 本次探针结果 | 对应代码原因 |
| --- | --- | --- |
| 主界面自动恢复提示 | 英文 15pt 测得需高 27，固定行高 24 | `MainUi.cs` options 固定行高，没有随内容增长 |
| 主界面“完整记录”链接 | 英文 15pt，112 宽下需两行约 54，高度只有 28 | history 固定宽列、固定标题行 |
| 完整记录顶部按钮 | 英文 15pt，按钮高 40，Y=3，加边距超出 42 高的顶部容器；最后按钮也越过右边界 | 不换行 FlowLayoutPanel 固定高 42 |
| 设置三页共用顶部按钮 | 英文 15pt，按钮 Y=5、高 40，超过容器高 42 | 固定高 42，没有按字体/边距计算 |
| 诊断页来源与识别说明 | 15pt 合成四行诊断样本在窄列内折成更多行，需文字高 189，控件高 120 且上下各 padding 8；渲染只显示前部 | 顶部固定行 120，说明 Label 不可滚动；下方工具固定行 205，挤压中间统计区 |
| 诊断页长选项文字 | 15pt 渲染中“详细诊断”“只读 UIA 对照”的英文说明右侧裁切 | 自动大小 CheckBox 没有按工具区可用宽度约束/换行；现有通用设置适宽函数也未覆盖这页 |
| 窗口选择顶部说明 | 英文 15pt 需文字高 54，控件高 65 扣除上下 padding 24 只剩 41 | `WindowPicker.cs` 固定高 65 |

以上代表样例证明问题跨页面存在，但不表示用户截图中所有裁切都由相同字体/DPI 引起。诊断文字为自造显示样本，没有读取真实聊天内容；不能将该样本当作故障机原始诊断。

初步方案：嵌入设置页取消独立窗体最小宽度约束，统一由父客户区和内容布局决定可用宽度；按实际字体、可用宽度、padding/margin 计算说明行和工具栏高度，窄宽度时按钮流式换行并增长高度。诊断说明和工具区明确支持换行/垂直滚动，避免以增加顶部固定高的办法继续挤掉中间统计；长 CheckBox 统一适宽。主窗体状态和链接也按内容布局，保留原生系统边框及现有功能行为。

## 当前修改方案与验收边界

1. 先修共用日志横向视口，再修固定高度/窄宽度的已复现裁切；保留纵向滚动阅读与选择复制。
2. 使用统一内容适宽、按内容定高和必要滚动，覆盖主界面、完整记录、设置三页及弹窗；为剩余候选先做代表复现，避免不必要重写。
3. 代表验收包括中文/英文、默认/最小宽度、放大字体、实际多屏 DPI 切换、长状态/标题/诊断、滚动末尾与文本复制。此前的本地 96 DPI 探针不代替用户设备验收。
4. 时间戳始终可见，全文有读取入口；按钮与关键状态不能被裁切；不通过缩小字体或隐去文字掩盖问题。不修改暂停恢复判断、不读取普通恢复的输入文本、不增加草稿门槛、不更改 1.5 秒输入让行。

本轮完成的是排查与可执行计划，以上 UI 修正尚未实现，故障设备的文字问题尚未验收通过。
