# 最小化操作可行性研究（2026-10-28）

## 用户目标与本轮结论

用户要求研究目标最小化时能否继续操作，希望最小化不影响 CAR。当前产品仍为 1.1.17；本轮完成代码检查、官方资料核对、自有窗口探测和真实 Codex 已有调试接口的只读检查，没有修改产品源码、发布版本或发送真实聊天消息。

结论：最小化不等于进程不能接收操作。已在自有 Chromium 窗口证明，通过 CDP 可以在窗口始终最小化时操作本地按钮、输入中文多行文本并读回本地提交结果，期间前台窗口和鼠标位置保持不变。当前 CAR 的截图识别路径不能据此直接放开：自有原生窗口在最小化后已响应按钮操作，但 WGC 仍返回旧图，独立捕获超时。真实 Codex 最小化下的恢复、额度控制、切换和任务发送尚未通过完整验收，不能宣称产品已经支持。

## 当前实现的阻断位置

| 位置 | 已确认的行为 | 修改方向 |
|---|---|---|
| `src/Native.cs` 的 `Target.ValidateIdentity` | 在核实进程身份后，因 `IsIconic` 拒绝目标；身份与界面可操作性混合 | 拆出纯身份核验；按传输能力单独判断可操作性 |
| `src/App.cs` 的 `TickBackground`、`WindowCapture.cs`、`BackgroundClick.cs` | 捕获、定位、投递前分别拒绝最小化；成功依赖新的方块帧 | 保留图像路径现有保护，增加语义状态与确认路径 |
| `src/ComposerWorker.cs` 的 `Valid`、`DebugComposer.cs` 的 `Operation` | 即使使用 CDP，也间接调用上述最小化检查 | 仅在后端已证明不依赖窗口显示时允许最小化，保留身份、期限与输入让行核验 |
| `AccessibleComposer.SingleEditor`、`SendButton` | 过滤 `IsOffscreen`；输入路径要求编辑器及系统前台焦点 | 不能直接删除过滤或焦点条件；需独立验证后台读写能力及副作用 |
| `src/ScopeControl.cs` | 原生侧栏切换包含激活、滚动和屏幕可见性要求 | 要支持范围轮询，必须另有可确认目标身份的后台导航路径 |
| `src/TaskSchedule.cs` 的 `TimedCurrent`、`src/QuotaUi.cs` 的 `QuotaCurrent` | 共享最小化检查；定时任务和额度恢复同样受阻 | 新后端需贯穿这些流程，不能只修普通三角形恢复 |

`UsageUi.UsagePulse` 的额度查询由独立计时器运行，不依赖截图或窗口是否最小化；这是代码检查结论，本轮没有另行执行真实账号查询。CAR 自身主窗口最小化与目标窗口最小化也应分开验收：未发现以 CAR 自身 `WindowState` 暂停监测的分支。

## 探测方法与实际结果

探测代码、原始结果及隔离浏览器配置均在忽略目录 `.local/minimized-research-2026-10-28/`，不进入源码包。测试进程有截止时间，完成后关闭自有窗口与隔离浏览器；最终检查未发现该目录对应的 Chrome 进程残留。没有最小化、恢复、重启或写入真实 Codex 窗口，也没有给真实 Codex 打开调试功能。

### 1. 自有原生窗口：可接收操作，截图不能证明当前状态

使用 WinForms 自建窗口，按钮的两次操作分别将背景从红色改为绿色、蓝色。WGC 使用产品捕获代码的临时副本：只在忽略目录中绕过最小化检查，并保留最小化前的有效尺寸，用于区分“代码主动拒绝”和“系统实际提供何种画面”。产品源码未改变。

- 正常窗口捕获为红色，像素 RGB 为 `255,0,0`。
- 最小化后仍能发现自有按钮：UIA `IsOffscreen=true`，提供 `InvokePattern`；一次 Invoke 后实际计数为 1，窗口仍最小化。
- UIA 尝试期间观测到前台 HWND 变化；本轮未隔离其全部成因，不能据此保证 UIA 不改变前台。
- 对同一自有原生按钮投递 `BM_CLICK` 后，实际计数变为 2，窗口仍最小化；相对该次投递前的前台 HWND 不变。
- 此时持续 WGC 返回 `source=cached` 的红色旧图，图龄约 1.15 秒；独立捕获等待约 2 秒后超时。

这证明“操作可达”和“图像可验证”是两件事；图龄尚短也不等于图像反映刚发生的状态。自有原生按钮的 `BM_CLICK` 成功不代表 Codex 自绘按钮兼容，更不能用消息入队成功替代恢复确认。

### 2. 隔离 Chromium：始终最小化的 CDP 操作通过

使用本机 Chrome `156.0.8078.49`、独立配置和本地 HTML，无账号、外部页面或真实服务请求。通过自身调试接口将该测试窗口最小化，逐步核对 `Browser.getWindowBounds`：

| 阶段 | 窗口状态 | 可验证结果 |
|---|---|---|
| 操作前 | `minimized`；文档 `hidden` | 本地按钮计数 0，编辑器空 |
| `Runtime.evaluate` 操作本地按钮 | `minimized` | 计数 1，按钮状态变为 `running` |
| `Input.insertText` | `minimized` | `innerText` 精确读回 `CAR 最小化本地测试\n第二行` |
| 操作本地提交按钮 | `minimized` | 编辑器空，本地输出与输入完全一致 |

最小化后的操作前后，独立原生只读助手核对前台 HWND、鼠标坐标均不变。此结果证明该 Chromium 测试环境的技术可行性，不是 Electron/Codex 实机恢复或服务端消息送达的验收。

### 3. 真实 Codex：只读检查发现现有 CDP 适配障碍

本机安装为 Codex `26.1021.3705.0`。发现主进程已监听本机回环调试端口；通过监听进程和安装路径核验所有权，仅读取目标列表、DOM 结构计数与可见性。没有读取聊天正文、草稿或账号令牌，没有执行点击、聚焦、输入或提交。

- 当次只读快照有两个匹配 `app://-/index.html` 的 page。产品 `DebugComposer` 要求恰好一个，当前会拒绝，不能随意选第一个页面。
- 页面中 `.ProseMirror[contenteditable=true]` 数量分别为 1 和 3，说明旧的全页单编辑器假设不适配多面板结构。
- 旧的当前聊天选择器在两页中均匹配 0；其中一页存在 `button[aria-current=page]`，旧选择器没有覆盖该结构。
- 对两个页面调用 `Browser.getWindowForTarget` 均返回 `Browser window not found`，不能直接照搬 Chromium 的该接口建立 Electron page 与 HWND 的映射。

上述是当次快照而非固定数量约定；真实页面可因面板和窗口生命周期而变化。此前版本记录中的“没有既有调试端口”是此前环境事实，本轮已发生变化。现有端口可用不等于当前 CAR 已适配，也不代表其他用户默认有端口。

## 初步实施方案

1. **分离身份与界面条件。** 保留进程 ID、启动时间、安装路径、窗口归属、账号、聊天绑定、期限和代次校验；将“需要未最小化/有新帧/有前台焦点”移到真正依赖这些条件的具体传输。现有 WGC/坐标消息路径继续拒绝最小化。
2. **先建立可靠的 CDP 目标绑定。** 复用已开放且可核实所有权的接口，处理多 page、多编辑器和原生侧栏按钮结构。首先在未最小化时用独立的原生聊天/窗口证据与 DOM 聊天身份交叉核验，再绑定 page、执行上下文、聊天与 composer。标题、页面顺序和矩形相同都不能单独授权；无法唯一绑定则等待。最小化、重载、面板变化后重新核验，重启或账号变化使旧绑定失效。Electron 不支持的窗口查询不能当作通用映射。
3. **增加完整的语义后端。** 现有 `IComposer` 只覆盖检查、输入和发送，需要增加明确的暂停、恢复与导航能力。对暂停按钮采集真实结构样本，核对按钮语义/局部 SVG、所属 composer、禁用状态及运行状态，不能只找通用发送按钮。每次重新解析当前绑定目标；提交后确认同聊天的新运行状态或新消息，不能以 `.click()` 返回作为成功。后台确认失败不切换成旧截图确认，也不重复发送。
4. **接通所有相关流程。** 普通恢复、额度不足暂停与额度恢复、定时恢复、多条一次性任务、项目/聊天范围轮询共用后端能力和保护条件，避免某条路径仍隐含要求前台。保留连续 1.5 秒输入空闲、草稿/附件/问答/语音保护、未知额度阻断和动作结果不明处理。
5. **无 CDP 环境单独验证 UIA。** 实测真实 Codex 在最小化时是否保留可核验聊天、运行状态、暂停/恢复按钮和可用的后台控件模式；操作前后校验窗口仍最小化、前台和鼠标不变。原生测试窗口有 `InvokePattern` 不足以证明 Codex 兼容。UIA 阻塞继续使用有期限的自有辅助进程，不能在监测线程等待。
6. **明确兼容边界。** 未证明可用的后端继续显示等待。短暂后台还原、完成后再最小化可以另外研究，但它改变目标窗口状态，不属于“始终最小化”的验收；本轮未将其设为用户已接受的默认后备，也不自动开启调试或修改真实客户端启动配置。

优先顺序：先完成真实 CDP 的唯一绑定与只读状态，再验证一个真实暂停聊天在最小化下恢复且状态确认，随后覆盖额度与任务/导航。产品修改和发布尚未进行；用户本轮要求研究，未把测试窗口结果直接作为正式支持交付。

## 验收条件与未决事项

- 目标始终最小化，普通恢复及已支持后端的暂停、输入、发送、范围切换可分别确认；鼠标与前台不变。CAR 自身最小化另测。
- 至少覆盖单聊天、多个 page/编辑器、多窗口绑定、中文多行、已有草稿、用户输入中断、问答、未知/低额度和到期任务。
- 重启/账号变化/目标重载、错误 page/聊天、迟到结果及超时不授权动作；结果不明不重复提交。
- 最小化后恢复操作系统窗口时，原聊天、草稿和项目状态符合已确认动作，历史只记实际确认的恢复。
- 无端口环境是否有足够的 UIA 后台能力尚未实测；若无，则无法承诺所有默认安装均能始终最小化操作。
- 真实暂停按钮的 DOM/辅助功能状态、最小化后状态更新，以及语义结果与实际恢复的一致性仍需真实场景证明。本轮没有触发真实服务端额度重置。
