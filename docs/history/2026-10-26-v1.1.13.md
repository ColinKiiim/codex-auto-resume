# 1.1.13 实施与测试精简记录

日期：2026-10-26（Asia/Shanghai）

## 本版完成的工作

- 原待办 9 的功能实现：只复用一个本机当前 Codex 登录，隐藏启动目标安装内的 App Server，以逐行 JSON 读取账号与额度；不增加账号库、OAuth、令牌读取/保存或直接 HTTP 回退
- 首页底部恢复次数右侧显示短周期、细条和剩余百分比；点击查看来源、重置时间、最后成功读取及刷新。首页尺寸不变，查询失败不改变恢复流程
- 查询前后核对账号、来源与文件元数据，目标或登录来源变化时取消旧查询。设置超时，排空 stderr，不记录原始响应；用 Windows Job 只管理本次创建的进程树，取消/退出时关闭
- 原待办 10：移除首页“更换”，将手动选择窗口放在“设置 → 常规 → 高级定位”；自动发现和多窗口确认保留
- 整理当前 TODO 与历史讨论，AGENTS 明确同轮移出已完成事项、部分完成只保留剩余验收，私人临时材料放根目录 `.local/`，共享规则与必要决策历史保留 Git 跟踪

## 用户要求的测试精简

用户明确要求删除所有非必要测试，只保留不得不留的测试。本版删除字体/编号/字重/缩放/位置的穷举矩阵、许可证/图标/布局等低风险重复检查、冗长演示与多套重复便携验证。

- 删除 `UiLayoutTests.cs`、`ChromiumTests.cs`、`BackgroundTests.cs`、`TargetCaptureProbe.cs`、`migration-audit.ps1`、`portable-smoke.ps1` 及失效构建入口
- 默认回归收敛为 73 次断言，分为识别误点、恢复输入、捕获证据/取消、更新完整性/回退和当前登录额度协议五组；这是断言数，不是独立实机场景数
- 主窗体流程只保留默认观察、暂停保持、一次遮挡恢复和多候选不误点。此前长流程的一次前台恢复等待因目标没有获得前台而未通过；没有宣称该次通过，也没有放宽产品的前台要求。鼠标在数秒监测期间可能被用户移动，不用这类长区间比较推断 CAR 移动了鼠标；实际消息点击的指针/前台保持由内置后台诊断检查
- 保留系统 OCR 问答保护、真实跨进程更新成功/回退、单 EXE 后台便携、真实本机额度读取、发布不可覆盖和版本系列保护；发布验证不再依赖本机已有旧版附件
- 不再维护默认执行的外观/布局测试。额度布局曾在测试精简前完成中英 100/150/200% 布局与临时图像核对；这是本次的检查记录，不是继续维护该套件的理由
