# 1.1.17 实现与验收 · 2026-10-27

用户要求执行全部当前待办并发布。产品决定为项目范围自动遍历聊天、一次性任务到点发送各自指令；测试仅使用用户指定的独立对话，内容为问候及不修改本地文件/代码的约束。用户中途明确暂停并说明聊天变化是其手动切回，本轮按其恢复指令继续，没有把那次变化记作程序自行导航故障。

## 实现

- 指定范围按当前 Codex 进程、侧栏运行时标识及完整标题绑定，动作前重读当前项/工具栏/文档；同名对象拒绝。重启重新确认。项目轮询可展开、滚动到已暴露对象并投递一次原生切换；必要时先请求激活。确认超时不重复投递，保留人工重新确认入口。
- 每条一次性指令拥有独立 ID、UTC 时间、目标、文案、状态和账号摘要；到点可切回绑定聊天。相同目标严格按时间排队，前条等待不会被后条超过，结果不明阻止该目标后续任务。写入前原子保存执行预留；重启不重放，待执行任务须重新绑定。默认继续文案不动态覆盖任务。
- 真实空框以原始辅助树中的 `placeholder` 结构及完整后代核验，不能仅凭占位文字判断。焦点等待保持时限和输入让行；一次写入和发送后的控件重建只在原聊天内重新取证。精确用户消息气泡与空框共同确认送达，兼容多行消息和很快完成的回复。
- 已确认真实恢复保存 UTC 历史，演示和未确认点击排除；悬浮为最近 24 小时最多四条，记录页浏览全部并保留位置。设置与记录嵌入主窗口，暂停操作仍可使用。
- 已保存恢复时间正确回填，草稿修改标明未保存；开关、到点、额度、输入、原聊天和待确认状态分别表达。展示不调用动作授权门控。事件日志使用目标摘要，不写任务正文。
- 系统允许后将持续及独立捕获会话设为无边框，所有新建/重连路径共用策略；拒绝、缺少 API 或设置失败保留正常捕获与诊断说明。

## 本机实际验收

- 真实 Codex：隔离低额度驱动运行方块暂停，保持低额度时普通恢复不反向继续；额度恢复但时间未到仍不动作，到点后原对话恢复并由新运行帧确认。隔离值不是服务端真实额度耗尽或重置。
- 真实中文多行输入及消息送达已确认。首次测试发现占位值、控件重建和多行气泡的适配问题，早期不明结果均停止且未自动重发；修复后正式辅助进程返回 Submitted，并从独立对话记录核对收到的问候及回复。
- 真实草稿：占位提示同文的实际草稿仍判为非空，正式辅助进程拒绝覆盖/发送；只清除了本次自行创建且精确匹配的测试草稿。
- 真实独立任务：两条不同文案均发送并确认；发现后条越过等待前条的缺陷后修复，最终真实顺序复验为甲确认完成后乙才执行。其他目标队列独立，不明结果不重放。
- 真实侧栏读取和同项目切换返回通过；部分后台状态仍出现原生导航确认超时，安全停止并保留为后续兼容验收。操作不明不记为成功。
- 原故障电脑的遮挡漏检专项由用户明确确认通过；没有补写其未提供的时间戳或设备配置。第二台电脑额度读取沿用用户此前确认。
- 无边框本机权限 Allowed、持续会话属性 false、持续/独立复核图像有效；正式 UI 的视觉观察和另一设备结果分别记录，不以属性成功替代另一设备黄框验收。其他客户端要求的边框不受 CAR 单独控制。
- 设置/记录在同一个主窗口显示，设置可滚动；时间回填、未启用执行、草稿标识与历史筛选的隔离检查通过。临时截图和原始侧栏/账号诊断不进入源码包。

默认构建与必要流程的最终执行结果见验证记录。基础断言包含代表性参数重复，不等于独立实机场景数量。尚需环境的事项已从实施计划中剥离，保留在当前 TODO；按用户既有发布决定交付当前实现。
