# 1.1.23：绑定限制清理、底部重试与界面修复

用户要求将限制清理和其他待修改事项一起实施。本次授权覆盖先前仅研究的底部重试方案及全界面文字问题；不重新加入普通恢复草稿检查。

## 实现

- UIA 按主编辑器祖先定位聊天文档，内置浏览器的 RootWebArea 不参与全局唯一计数；侧栏同名行不再是普通恢复必需项。CDP 页绑定可使用原生文档、已核验页面或归属当前进程的唯一非通用窗口标题/窗口几何证据，不再先强制成功完成依赖侧栏的 UIA 绑定
- 当前聊天 ID 优先使用 composer 上方的稳定元数据，不能把浏览器所属聊天标记当成当前聊天；普通观察可在同页更新绑定，动作仍核对进程、窗口、页面、聊天、编辑器和按钮实例。元素身份保存在节点属性中，cloneNode 不会复制它
- 状态动作和显式内容提交分开。附件、无关弹窗、工具区的提交/跳过和 Notes 编辑器不阻断普通恢复；显式发送仍保留已有内容、附件、问答与结果不明保护。识别真正问答区域，而非全页看到一个提交按钮就停
- 去掉输入区 14 按钮和固定上溯层数门槛；兼容引用式无障碍名称。仍需有可识别的主输入区和动作身份，歧义不是任意选取对象的依据
- 已核验聊天的 transcript 内容单元中，最新 capacity 系统 aside 的唯一可用 Retry 优先；用户内容、历史项、其他网页和输入区不提供重试授权。离屏但仍挂载的按钮可直接投递，未挂载时保留普通恢复入口，不强制滚动。按钮/错误单元变化使旧证据失效；不等待可点击按钮的显示倒计时结束
- 投递和运行确认分开。动作完成后允许应用正常替换按钮并检查新状态；同一失败重试结果不明时，主进程记住其身份，不重新投递同一按钮。普通恢复原有冷却未改
- 侧栏已有可核验 CDP 时使用项目/聊天稳定 ID，支持同名对象和冷态 UIA 不可用；导航前、投递中、投递后保持当前聊天、目标项目、输入 tick、前台和最小化复核。无 CDP 仍保留原生后备
- 绑定失效清空首页及诊断页旧状态示意，日志记录 action-source / block-reason / binding-note。示意与原始截图继续区分
- 最近进度强制左侧原点，完整记录保留横向阅读位置；嵌入设置取消独立 Form 的 540 宽度约束。内容行与工具栏自动适宽，长复选框使用实际换行高度，诊断、选择、更新说明可滚动/换行；窄额度条改为文字摘要，完整详情入口保留
